## A1과 A2를 나누는 이유

첫 두 단원에 필요한 성취기준은 다음 다섯 개뿐이다.

- 큰 수: `[4수01-01]`, `[4수01-02]`
- 각도: `[4수03-02]`, `[4수03-24]`, `[4수03-25]`

이 코드는 기존 초3 세트에서 사용하지 않았고 학년·학기 공유 후보에도
포함되지 않는다. 따라서 A1에서는 다섯 코드의 초4-1 배치와 라벨만
승인한다. 곱셈과 나눗셈·막대그래프의 학년군 공유, `[4수04-03]`의 학기
공유, 초4-2 순서와 배치는 A2로 미룬다.

배치 원장은 단원별 승인 상태를 기록해야 한다. 초4 DiagnosisSet은
승인된 단원과 앵커만 선언할 수 있어야 하며, 미승인 단원·앵커는
발행 게이트가 차단한다.

## A1 승인 범위와 앵커 절 대응

A1은 다음 배치만 승인하며 A2 대상에는 영향을 주지 않는다.

- 1단원 큰 수
  - `[4수01-01]`: 10000 이상 큰 수의 자릿값, 위치적 기수법, 읽고 쓰기
  - `[4수01-02]`: 수의 계열, 크기 비교, 비교 방법 설명
- 2단원 각도
  - `[4수03-02]`: 각과 직각 이해, 직각과 비교한 예각·둔각 구별
  - `[4수03-24]`: 1도와 각도기를 이용한 측정·어림
  - `[4수03-25]`: 삼각형·사각형 내각의 크기 합 추론·설명

원문의 각 절은 최소 한 학습 단계에서 독립적으로 관찰한다. 앵커 ID만
형식적으로 단계에 붙이는 것은 coverage로 인정하지 않는다.

## Seam S1 — 큰 수

완료 목표:

- 학습 단계 6개
- direct 6개 + transfer 6개 = 판단 12개
- 오답 24개
- 단계별 오개념 2개 = 오개념 12개
- 각 오개념이 direct와 transfer 두 판단에서 반복 관찰됨
- 예상 시간 약 6분

| 단계 | 관찰 행동 | direct | transfer |
|---|---|---|---|
| `large-number.place-value` | 자리 숫자와 자리값 연결 | 자리표에서 지정 자리값 고르기 | 값에 맞는 자리 이름 고르기 |
| `large-number.positional-notation` | 같은 숫자도 자리에 따라 값이 달라짐 | 두 자리의 같은 숫자가 나타내는 값 비교 | 자리를 옮기면 값이 몇 배가 되는지 판단 |
| `large-number.read-write` | 숫자와 한글 읽기 변환 | 숫자를 한글로 읽기 | 한글 읽기를 숫자로 쓰기 |
| `large-number.sequence` | 큰 수의 계열 이해 | 다음 수 고르기 | 뛰어 센 단위 찾기 |
| `large-number.compare` | 큰 수의 크기 비교 | 두 수 비교 | 조건에 맞는 가장 큰 수·작은 수 만들기 |
| `large-number.compare-reasoning` | 비교 방법 설명 | 비교 근거 문장 고르기 | 잘못된 비교를 바르게 고친 근거 고르기 |

오답은 자리 이름 한 칸 밀림, 자리 숫자와 자리값 혼동, 자리 이동을
덧셈으로 처리, 배수를 한 자리 작게 적용, 만 단위를 잘못 끊어 읽음,
뛰어 세는 단위를 한 자리 작게 적용, 자릿수 무시, 최고 자리가 같은데도
첫 자리만 비교하는 등의 규칙으로 실제 선택지 값을 산출해야 한다.

### `place-value-chart` 시각자료

기존 `data-table`은 열 제목이 `종류 / 수`로 고정된 세로 표이므로 자리표로
재사용하지 않는다.

```ts
type PlaceValueChartVisual = {
  kind: "place-value-chart";
  digits: number[]; // 최고 자리부터 4~9자리, 각 0~9
  ask: "value" | "place-name";
  highlightIndexes?: number[];
};
```

- 자리 이름은 배열 길이에서 파생해 콘텐츠 오기를 막는다.
- 실제 `<table>`을 사용해 자리 이름을 열 머리글로, 숫자를 한 행으로
  나타낸다.
- `highlightIndexes`는 0부터 `digits.length - 1`까지의 중복 없는 인덱스
  1~2개만 허용한다. 필드를 사용할 때 한 자리의 자리값을 물으면 1개,
  같은 숫자가 놓인 두 자리의 값을 비교하면 2개를 강조한다.
- `ask: "place-name"`은 그림에 정답 위치를 먼저 표시하지 않는다.
  `highlightIndexes`를 생략하고, prompt에 `30000을 나타내는 자리는
  어디일까요?`처럼 값을 제시해 값에서 자리 이름을 찾게 한다.
- 숫자 읽고 쓰기·수 계열·수 비교·비교 근거 단계는 자리표가 수학적
  행동에 필요할 때만 사용하며, 필요하지 않은 판단은 `visual: none`으로
  작성한다.
- 390px에서도 가로 스크롤 없이 보이게 하되, 한 글자씩 지나치게 작아지면
  두 개의 네 자리 묶음으로 시각적으로 구분한다.
- 이미지 생성은 사용하지 않는다.

완료 게이트:

- TypeScript·Zod·SQL·UI 렌더러·학생 렌더 결정론/정답 비노출 테스트의
  다섯 경로가 일치한다.
- 자리 수, 숫자 범위, `place-name`에서 강조 금지, 강조 인덱스
  범위·중복에 대한 음성 테스트가 있다.
- 12/24/12 카운트, 단계별 고유 근거 6개, 앵커 원문 6개 절의 단계
  대응과 오개념 반복 관찰을 기계 검증한다.
- S1만 있을 때 세트 `manifest.estimatedMinutes`를 6으로 기록하고
  checksum을 다시 고정한다. 학생 단원 카드는 기존
  `Math.max(3, Math.ceil(judgmentCount / 2))` 계산으로 12문항·약 6분을
  표시하며, 단원 객체에 새 시간 필드를 추가하지 않는다.
- 초3 체크섬과 고정 산출물은 바뀌지 않는다.
- 1280×720, 768×1024, 390×844에서 12문항 전체를 확인한다.

## Seam S2 — 각도

완료 목표:

- 학습 단계 6개
- direct 6개 + transfer 6개 = 판단 12개
- 오답 24개
- 단계별 오개념 2개 = 오개념 12개
- 예상 시간 약 6분

| 단계 | 관찰 행동 | direct | transfer |
|---|---|---|---|
| `angle.right-angle` | 각과 직각 이해 | 변 길이가 다른 한 각을 보고 직각에 대한 바른 설명 고르기 | 책 모서리를 한 각으로 단순화한 그림에서 꼭짓점·두 변 관계를 바르게 설명한 문장 고르기 |
| `angle.classify` | 직각과 비교해 예각·둔각 구별 | 한 각을 예각·직각·둔각으로 구별 | 기준 직각과 함께 표시된 한 각의 관계 설명 고르기 |
| `angle.protractor-measure` | 1도와 각도기 측정 | 안쪽·바깥쪽 눈금 읽기 | 한 각도기 그림의 놓인 방법이 바른지와 그 이유 고르기 |
| `angle.estimate` | 직각을 기준으로 어림 | 직각과 비교해 어림값 고르기 | 생활 속 각의 어림값 고르기 |
| `angle.triangle-angle-sum` | 삼각형 내각 합 추론 | 두 각이 표시된 삼각형의 나머지 각 구하기 | 세 각의 수치 조합 중 삼각형이 될 수 없는 것을 판단하고 이유 고르기 |
| `angle.quadrilateral-angle-sum` | 사각형 내각 합을 여러 방법으로 추론 | 세 각이 표시된 사각형의 나머지 각 구하기 | 대각선으로 나눈 두 삼각형을 이용한 설명 고르기 |

주요 오개념은 변의 길이를 각의 크기로 판단, 안쪽·바깥쪽 눈금 혼동,
0° 기준선 미정렬, 직각을 100°로 어림, 90°를 예각·둔각에 포함하는
경계 오류, 삼각형에 직각이 있다고 가정, 두 알려진 각의 차를 답으로
사용, 사각형에도 180°를 적용, 네 각을 모두 90°로 가정하는 오류다.
각 오답 근거는 실제 표시된 선택지 값까지 산출해야 한다.

내각 합 자체인 180°·360°를 정답으로 먼저 묻지 않는다. 앞 문항에서
정답을 알려 뒤 문항을 오염시키지 않도록, 빠진 각을 구하거나 분할 추론
방법을 고르게 한다.

### `angle-figure` 시각자료

```ts
type AngleFigureVisual = {
  kind: "angle-figure";
  degrees: number; // 1~179, 별도 정답 텍스트로 표시하지 않음
  mode: "bare" | "protractor";
  rayLengths?: [number, number];
  referenceRightAngle?: boolean;
  protractorPlacement?: "aligned" | "vertex-off" | "baseline-off";
  label?: string;
};
```

- 이 계약은 의도적으로 한 판단에 한 각만 렌더한다. 여러 그림을 고르는
  문항은 만들지 않고, 그림 하나를 본 뒤 예각·직각·둔각 또는 측정 방법의
  근거를 텍스트 선택지로 고르게 한다. 이는 기존 초3
  `circle.equal-radii`의 단일 그림 + 관계 설명 선택지와 같은 방식이다.
- `bare` 모드는 숫자와 눈금을 표시하지 않는다.
- `protractor` 모드는 각도기 읽기 자체가 목표이므로 안쪽·바깥쪽 눈금과
  10° 간격 눈금 숫자를 의도된 관찰 정보로 표시한다. `degrees`를 별도
  정답 라벨로 출력하지 않는다.
- `protractorPlacement`를 생략하면 `aligned`다. `bare` 모드에서는 이
  필드를 금지한다. direct는 `aligned` 그림에서 안쪽·바깥쪽 눈금 혼동을,
  transfer는 `baseline-off` 그림에서 0° 기준선 미정렬을 관찰한다.
- 이 단계의 두 공유 오개념은 `안쪽·바깥쪽 눈금 방향 혼동`과
  `0° 기준선 정렬 상태를 반대로 판단함`이다. direct의 올바르게 정렬된
  그림에서는 반대 눈금 값과 `기준선이 어긋나 잴 수 없다`를 오답으로,
  transfer의 어긋난 그림에서는 `반대 눈금을 읽으면 된다`와
  `이미 기준선이 맞다`를 오답으로 사용한다. 두 오개념이 모두 두
  판단에서 실제 선택지로 반복되며, 제목과 선택지 산출이 일치해야 한다.
- `vertex-off`와 `baseline-off`는 각도기 중심 또는 0° 기준선이 벗어난
  상태를 실제 SVG 좌표로 표현한다. aria는 `각도기의 중심이 꼭짓점에서
  벗어나 있다`, `0 눈금이 한 변에서 벗어나 있다`처럼 보이는 사실만
  말하고 `바르게/잘못 놓였다`는 판정을 대신하지 않는다.
- bare 모드에서 각 크기를 말하거나 비교 결과를 대신 판단하는 aria를
  금지한다.
- protractor aria는 기준선·두 눈금의 존재를 설명하되 읽은 각도를 직접
  말하지 않는다.
- 순수 시각 비교의 접근성 한계를 줄이기 위해 모든 선택지는 그림 라벨이
  아니라 텍스트 관계·근거로 제공한다. 같은 단계의 transfer 판단도
  한 그림에 대한 근거를 고르게 한다.
- `angle.right-angle`과 `angle.classify`의 시각 판단은 aria가 각의
  종류를 대신 말하면 정답이 노출되므로 시각 의존 판단임을 교사 검토
  문서에 표시한다. 이 결과만으로 학생의 개념 부족을 단정하지 않는다.
- `angle.estimate` transfer의 생활 맥락은 prompt/context의 구체적인
  사물 이름으로 제공하고, 시각자료는 같은 사물을 흉내 낸 장식 그림
  대신 한 각을 정확히 보여 주는 `angle-figure`를 사용한다.
- SVG로 결정론적으로 그리며 이미지 생성은 사용하지 않는다.

### `polygon-angle-diagram` 시각자료

하나의 각만 표현하는 `angle-figure`로 삼각형·사각형 내각과 대각선
분할을 대신하지 않는다.

```ts
type PolygonAngleDiagramVisual = {
  kind: "polygon-angle-diagram";
  polygon: "triangle" | "quadrilateral";
  mode: "find-missing" | "verify-claim";
  angles: Array<{
    label: string;
    value: number | null; // null은 물음표
  }>;
  diagonal?: boolean;
};
```

- `angles.length`는 삼각형 3개, 사각형 4개다.
- `find-missing`에는 `null`인 각이 정확히 한 개이고,
  `verify-claim`에는 모든 각의 수치가 있다.
- 알려진 각은 1~179 정수이며, 알려진 합에서 계산한 나머지 각도
  1~179가 되어야 한다.
- `diagonal`은 사각형에만 허용한다.
- 각 라벨은 공백이 아닌 고유 문자열이다.
- 렌더러와 aria는 표시된 각, 물음표, 대각선만 설명하고 180·360 또는
  계산 결과를 덧붙여 말하지 않는다.
- `verify-claim` 그림은 주장의 참·거짓과 관계없이 항상
  `그림보다 표시한 수를 보고 판단해요`를 보여 주어, 안내의 유무가
  정답 단서가 되지 않게 한다.
- 알려진 수치와 물음표를 aria에서도 그대로 제공하므로
  `angle-figure`의 순수 시각 비교와 달리 스크린리더 사용자가 같은 수치
  추론을 수행할 수 있어야 한다.
- SVG로 결정론적으로 그리며 이미지 생성은 사용하지 않는다.

완료 게이트:

- `angle-figure`와 `polygon-angle-diagram`의
  TypeScript·Zod·SQL·UI 렌더러·학생 렌더 결정론/정답 비노출 테스트의
  다섯 경로가 일치한다.
- 0°·180°, 모드와 금지 속성 조합, `bare`의 protractorPlacement 지정,
  정답 노출에 대한 음성 테스트가 있다.
- 다각형별 각 수 불일치, 물음표 0개·2개, 합 초과, 삼각형의 대각선,
  중복 라벨을 차단하는 음성 테스트가 있다.
- 정답 라벨이 내각 합 `180`·`360` 그 자체인 단독 수치 답이 아님을
  `label.trim()`과 `/^(180|360)(도|°)?$/`로 검사한다. 분할 방법을
  설명하는 문장 안에서 `180`을 근거로 사용하는 것은 허용한다.
- 누계 24판단·48오답·24오개념·단계별 고유 근거 12개와 다섯 앵커
  원문 절의 완전한 단계 대응을 검증한다.
- S2를 합친 뒤 세트 `manifest.estimatedMinutes`를 12로 갱신하고
  checksum을 다시 고정한다. 각도 단원 카드도 기존 판단 수 계산으로
  12문항·약 6분을 표시한다.
- 세 화면 크기에서 각 그림 비율, 눈금 가독성, aria, 가로 넘침을 확인한다.

## 선수 관계와 발행

큰 수·각도에는 근거가 충분한 초3 선수 연결이 없으므로 U9.1에서 새
선수 그래프를 만들지 않는다. 느슨한 주제 유사성이나 도구 유사성을
선수 관계로 승격하지 않는다. 단원 내부 순서는 `prerequisiteStageIds`로
표현한다.

두 seam 모두 `review` 상태로 유지한다. 자동 테스트 통과는 교사 승인을
대신하지 않는다. 각 seam 종료 후 문항, 오답 산출, 오개념 제목을 교사가
검토하는 체크포인트 B를 둔다.
