# 학생 수학 풀이 과정 분석 아이디어 노트

작성일: 2026-06-30  
상태: 아이디어 확장 중인 살아있는 문서

## 0. 현재 구현 기준

- 학생 풀이 화면은 앞으로만 진행한다.
- 이전 단계 버튼과 되돌아가기 기록은 제거한다.
- 이유: 뒤 단계에서 본 정답 단서가 앞 단계 판단을 오염시킬 수 있기 때문이다.
- 교사 화면은 현재 학생이 방금 푼 세션 기록만 기준으로 진단한다.
- 샘플 학생 데이터는 현재 풀이 진단에 섞지 않는다.
- 학생 화면에는 정답 단서, 오답의 특징, 교사용 진단 문구를 노출하지 않는다.
- 오래된 결정 로그에 남아 있는 `이전 단계로 돌아가기` 관련 내용은 폐기된 초안으로 본다.
- `npm test` 하네스가 학생용 진단 문구 누출, 정답 막대 노출, 이전 단계 기능 재도입, 샘플 학생 데이터 혼합을 막는다.

## 1. 출발점

기존의 수학 학습 서비스는 대체로 학생이 제출한 최종 답을 기준으로 `정답` 또는 `오답`을 판단한다. 하지만 최종 답만으로는 학생이 어디에서 막혔는지 알기 어렵다.

우리가 만들고 싶은 방향은 다음과 같다.

> 학생이 수학 문제를 푸는 과정을 관찰하고, 어떤 개념 단계에서 이해가 흔들리는지 분석하는 시스템.

즉, 목표는 단순 채점기가 아니라 `풀이 과정 기반 진단 도구`다.

## 2. 핵심 문제의식

학생이 틀린 답을 냈을 때 실제 원인은 다양하다.

- 문제를 잘못 읽었다.
- 필요한 개념을 떠올리지 못했다.
- 식은 맞게 세웠지만 계산에서 실수했다.
- 이전 단원의 개념이 부족해서 현재 문제를 해결하지 못했다.
- 풀이 전략은 맞았지만 중간 단계 표현이 불안정했다.
- 답은 맞았지만 우연히 맞았고, 개념 이해는 부족할 수 있다.

최종 답만 보면 이 차이를 구분할 수 없다. 따라서 학습자에게 필요한 피드백도 뭉뚱그려진다. 이 서비스의 가치는 바로 이 지점을 세밀하게 나누는 데 있다.

## 3. 내가 보는 제품의 중심 가설

내 의견으로는 이 아이디어의 핵심은 `정답률 향상`보다 `오개념의 위치를 찾는 것`에 있다.

정답률은 이미 많은 서비스가 제공한다. 하지만 교사와 학부모가 정말 알고 싶은 것은 다음에 가깝다.

- 이 학생은 어느 단원부터 흔들렸는가?
- 틀린 이유가 계산 실수인가, 개념 부재인가?
- 같은 유형을 반복해서 틀리는가?
- 풀이 순서 중 어느 단계에서 사고가 끊기는가?
- 지금 더 어려운 문제를 줄 수 있는가, 아니면 이전 개념으로 돌아가야 하는가?

따라서 서비스의 첫 번째 정체성은 `AI 채점기`보다 `수학 사고 진단 엔진`에 가까워야 한다.

## 4. 분석해야 할 풀이 단계

학생의 풀이 과정을 다음 단계로 나눠볼 수 있다.

| 단계 | 관찰할 것 | 진단 가능성 |
|---|---|---|
| 문제 이해 | 조건, 구하는 값, 단위, 문장 해석 | 문제 독해 오류, 조건 누락 |
| 개념 선택 | 어떤 공식, 정리, 전략을 선택했는지 | 개념 연결 실패, 단원 이해 부족 |
| 식 세우기 | 문제 상황을 수식으로 옮기는 과정 | 모델링 오류, 관계 파악 오류 |
| 변형/전개 | 등식 변형, 전개, 약분, 이항 등 | 절차 이해 부족, 기호 조작 오류 |
| 계산 | 사칙연산, 분수, 소수, 부호 처리 | 계산 실수, 연산 자동화 부족 |
| 검산/해석 | 답이 조건에 맞는지 확인 | 메타인지 부족, 답 검토 습관 부족 |

중요한 점은 `틀렸다`가 아니라 `어느 단계에서 틀렸는가`를 보여주는 것이다.

## 5. 데이터로 수집할 수 있는 것

초기에는 너무 복잡하게 시작하지 않는 것이 좋다. 가능한 데이터는 다음과 같다.

- 최종 답
- 학생이 선택한 풀이 단계
- 학생이 선택/생성한 분수막대 기록
- 학생이 선택한 풀이 이유
- 학생이 선택한 오답 보기
- 학생이 되돌아간 단계
- 학생이 되돌아간 횟수
- 되돌아간 뒤 선택을 수정했는지 여부
- 되돌아간 뒤 정답 또는 안정적인 선택에 도달했는지 여부
- 학생이 수정한 선택 순서
- 각 단계의 소요 시간
- 각 단계에서 멈춘 시간
- 각 단계에서 선택지를 바꾼 횟수
- 선택 후 `다음` 버튼을 누르기까지 걸린 시간
- 선택 후 `다음`을 누르기 전에 선택을 바꿨는지 여부
- 첫 선택까지 걸린 시간
- 분수막대 생성 시도 횟수
- 잘못 선택한 분수막대 기준/조각 수
- "모르겠음" 선택 위치
- "모르겠음" 버튼이 나타나기 전 체류 시간
- "모르겠음" 버튼이 나타난 뒤 실제로 선택했는지 여부
- "모르겠음" 선택 후 다음 단계에서 회복했는지 여부
- 같은 개념 문제에서의 반복 패턴
- 지우고 다시 쓴 횟수
- 힌트를 요청한 시점
- 힌트 이후 수정한 내용
- 풀이 중 멈춘 구간
- 같은 유형 문제에서 반복되는 오류 패턴

필기 인식까지 처음부터 넣으면 제품 난이도가 크게 올라간다. 그렇다고 서술형 입력을 기본값으로 두는 것도 위험하다. 초등학생에게는 수학 개념보다 글쓰기 부담이 먼저 커질 수 있기 때문이다.

MVP에서는 `조작형 입력 + 선택형 이유 선택`을 중심으로 시작하고, 짧은 서술은 선택 사항으로 두는 편이 좋아 보인다.

## 6. 가능한 사용자 경험

### 학생 화면

학생은 문제를 풀 때 한 번에 답만 입력하지 않는다. 대신 다음처럼 단계별로 생각을 남긴다.

1. 문제에서 중요한 조건을 고른다.
2. 분수막대로 주어진 분수를 만든다.
3. 분수를 같은 단위로 바꾸거나 비교하는 조작을 한다.
4. 자신이 한 선택의 이유를 보기 중에서 고른다.
5. 필요한 경우에만 짧게 설명을 덧붙인다.
6. 최종 답을 제출한다.

학생 입장에서는 부담이 너무 커지면 안 된다. 그래서 모든 문제에 이 방식을 적용하기보다, 진단용 문제나 오답 분석 문제에 우선 적용하는 것이 좋아 보인다.

화면 구성은 한 번에 한 판단씩 넘기는 방식이 좋다. 예를 들어 첫 화면에서는 "바로 더할 수 있을까?"만 묻고, 다음 화면에서 분수막대 조작을 하게 하며, 그 다음 화면에서 이유를 고르게 한다. 이렇게 하면 학생은 매 순간 하나의 생각에만 집중할 수 있고, 시스템은 각 판단을 독립적인 진단 신호로 기록할 수 있다.

### 교사 화면

교사는 학생별로 다음을 볼 수 있다.

- 문제별 정오답
- 단계별 오류 위치
- 반복되는 오개념
- 단원별 취약도
- 최근 개선된 부분
- 다음에 추천할 문제 유형

교사에게 가장 중요한 화면은 점수표가 아니라 `왜 틀렸는지 한눈에 보는 리포트`다.

### 학부모 화면

학부모에게는 너무 전문적인 수학 용어보다 이해 가능한 설명이 필요하다.

- "계산은 잘하지만 문제를 식으로 바꾸는 단계에서 어려움이 있습니다."
- "분수의 크기 비교 개념이 흔들려 이후 비례식 문제에서도 실수가 반복됩니다."
- "최근 2주 동안 식 세우기 정확도가 좋아졌습니다."

## 7. MVP 제안

처음부터 모든 수학 영역을 다루기보다 좁게 시작하는 것이 좋다.

### 추천 범위

- 대상: 초등학생
- 학년: 초등학교 5학년
- 영역: 분수
- 첫 사용자: 학생과 교사
- 문제 수: 첫 진단 세트는 10문항
- 입력 방식: 조작형 입력과 선택형 이유 선택 중심, 짧은 서술은 선택 사항
- 첫 조작 도구: 분수막대
- 분수막대 조작 방식: 기준/조각 수 선택 후 자동 생성
- 기본 단계 수: 문제당 6단계, 단 문제별 조정 가능
- 결과물: 학생용 단계형 풀이 경험, 교사용 부족 개념 진단 리포트

### MVP에서 꼭 보여줘야 할 가치

1. 같은 오답이라도 원인이 다르게 분류된다.
2. 답이 맞아도 풀이 과정의 불안정성을 잡아낸다.
3. 교사가 다음 수업에서 무엇을 보충해야 하는지 알 수 있다.
4. 학생에게 낙인감을 주지 않으면서도 교사가 개입 지점을 찾을 수 있다.

### 7.1 초등 분수부터 시작하는 이유

내 생각에도 분수는 첫 영역으로 좋다. 초등 수학에서 분수는 학생의 오개념이 매우 잘 드러나는 영역이고, 이후 소수, 비율, 비례, 방정식, 함수 이해에도 계속 영향을 준다.

분수가 좋은 출발점인 이유는 다음과 같다.

- 학생이 답을 맞혀도 분수의 의미를 제대로 이해했는지 확인하기 어렵다.
- 분모와 분자의 역할을 기계적으로 외우는 학생이 많다.
- 전체의 기준이 바뀌면 같은 분수도 다르게 해석된다는 점에서 자주 흔들린다.
- 통분, 약분, 크기 비교, 사칙연산이 모두 선행 개념 위에 쌓인다.
- 교사가 학생별로 어떤 분수 개념이 부족한지 알면 보충 수업을 바로 설계할 수 있다.

초기 포지셔닝은 이렇게 잡아볼 수 있다.

> 초등학생이 분수 문제를 푸는 과정을 분석해, 교사가 학생별 부족 개념을 빠르게 확인하고 바로 가르칠 수 있게 하는 도구.

### 7.1.1 초등학교 5학년으로 좁히는 이유

첫 MVP는 초등학교 5학년 분수로 잡는다.

내 의견으로는 5학년이 좋은 이유는 `분수의 의미를 처음 접하는 단계`와 `분수를 절차적으로 다루는 단계` 사이에 있기 때문이다. 학생이 분수를 완전히 낯설어하는 시기는 지나갔지만, 약분, 통분, 크기 비교, 덧셈/뺄셈에서 개념 이해와 절차 수행의 차이가 분명히 드러난다.

5학년 분수에서는 다음과 같은 진단 가치가 있다.

- 답만 보면 단순 계산 실수처럼 보이지만 실제로는 통분의 의미를 모르는 경우를 잡아낼 수 있다.
- 약분을 할 줄 알지만 왜 같은 분수인지 설명하지 못하는 학생을 구분할 수 있다.
- 분수 크기 비교에서 수직선 감각이 있는지 확인할 수 있다.
- 분모가 다른 분수를 더할 때 "같은 단위로 바꾼다"는 개념을 이해했는지 볼 수 있다.
- 문장제에서 전체 기준을 잘못 잡는 학생을 발견할 수 있다.

따라서 5학년 MVP의 핵심 질문은 이것이다.

> 이 학생은 분수 계산 절차를 틀린 것인가, 아니면 분수의 단위와 동치 개념을 이해하지 못한 것인가?

### 7.2 초등 분수에서 진단할 오개념 후보

| 영역 | 학생에게서 보이는 모습 | 교사가 확인해야 할 부족 개념 |
|---|---|---|
| 분수의 의미 | `1/3`을 단순히 숫자 두 개로만 본다. | 전체-부분 관계, 하나의 전체 기준 |
| 단위분수 | `1/4`와 `1/8` 중 어느 쪽이 큰지 헷갈린다. | 같은 전체에서 나누는 수가 많아질수록 한 조각은 작아진다는 개념 |
| 분모와 분자 | 분모가 크면 무조건 큰 수라고 생각한다. | 분모와 분자의 역할 구분 |
| 크기 비교 | `2/5`와 `3/7`을 분자 또는 분모만 보고 비교한다. | 통분, 기준량 맞추기, 수직선 감각 |
| 동치분수 | `1/2 = 2/4`를 외우지만 왜 같은지 설명하지 못한다. | 같은 양을 다르게 표현한다는 개념 |
| 약분과 통분 | 절차는 따라 하지만 언제 왜 쓰는지 모른다. | 표현 변환의 목적 |
| 분수 덧셈/뺄셈 | 분모끼리 더하거나 뺀다. | 같은 단위끼리만 더할 수 있다는 원리 |
| 대분수와 가분수 | 변환 과정에서 전체 수와 조각 수를 혼동한다. | 전체와 나머지 조각의 관계 |
| 문장제 | 상황을 분수식으로 옮기지 못한다. | 문제 이해, 기준량 파악, 식 세우기 |

여기서 중요한 것은 단순히 "분수 덧셈을 틀렸다"가 아니라, 왜 틀렸는지 나눠보는 것이다. 예를 들어 `1/2 + 1/3 = 2/5`라고 쓴 학생은 계산 실수라기보다 "분모가 다른 분수는 같은 단위가 아니다"라는 개념이 부족할 가능성이 크다.

### 7.3 학생과 교사가 함께 쓰는 흐름

학생과 교사를 첫 사용자로 잡는다면, 제품 흐름은 다음처럼 설계하는 것이 자연스럽다.

1. 학생이 분수 문제를 푼다.
2. 시스템은 최종 답뿐 아니라 중간 풀이, 선택한 전략, 수정 과정, 힌트 사용 여부를 기록한다.
3. 시스템은 오류가 생긴 단계를 추정한다.
4. 학생에게는 진단 결과나 오개념 분석을 직접 보여주지 않는다.
5. 교사에게 학생별 부족 개념, 해석된 행동 데이터, 추천 개입 방법을 보여준다.
6. 교사는 리포트를 보고 개별 피드백, 소그룹 보충, 다음 문제 배정을 결정한다.

이 흐름에서 학생 화면은 `문제 풀이를 방해하지 않는 것`이 중요하고, 교사 화면은 `수업 판단을 빠르게 돕는 것`이 중요하다.

### 7.4 교사용 리포트의 첫 모습

교사가 가장 먼저 봐야 할 정보는 점수보다 `보충해야 할 개념`이다.

예시:

| 학생 | 정답률 | 주요 부족 개념 | 관찰된 패턴 | 추천 지도 |
|---|---:|---|---|---|
| A | 70% | 통분의 의미 | 분모가 다른 분수를 분모끼리 더함 | 같은 단위 만들기 활동 |
| B | 85% | 분수 크기 비교 | 답은 맞지만 수직선 설명이 불안정함 | 수직선 위에 분수 표시하기 |
| C | 45% | 전체 기준 파악 | 문장제에서 전체가 무엇인지 놓침 | 그림으로 전체와 부분 표시하기 |

내 의견으로는 교사용 리포트는 처음부터 길고 완벽한 분석 보고서일 필요가 없다. 오히려 한 수업 전에 30초 안에 볼 수 있는 요약이 더 강력하다.

교사용 문장의 톤은 미사여구가 많으면 안 된다. 교사는 예쁜 문장보다 바로 이해되는 문장과 바로 수업에 쓸 수 있는 제안이 필요하다.

교사용 문장 원칙:

- 한 문장은 짧게 쓴다.
- 원인 추정은 단정하지 않고 가능성으로 표현한다.
- 근거, 해석, 지도 제안을 분리한다.
- "학습자가 수학적 사고의 구조화 과정에서..." 같은 긴 표현을 피한다.
- "공통분모 선택에서 선택을 3번 바꿨습니다. 통분 기준이 아직 불안정할 수 있습니다."처럼 바로 읽히게 쓴다.

교사용 문장 예시:

| 좋지 않은 문장 | 더 나은 문장 |
|---|---|
| 학생은 분수 연산 과정에서 개념적 이해의 체계화가 충분히 이루어지지 않은 것으로 보입니다. | 통분 기준을 고르는 단계에서 흔들렸습니다. 공통분모 찾기 활동이 필요합니다. |
| 분모와 분자의 연산 원리에 대한 이해가 다소 미흡할 가능성이 있습니다. | 마지막 계산에서 분모까지 더했습니다. 같은 조각끼리 더할 때 분모는 유지된다는 점을 다시 다루면 좋습니다. |
| 풀이 과정의 지속 시간이 상대적으로 길게 나타났습니다. | 동치분수 만들기 단계에서 오래 고민했습니다. 분수막대로 같은 양 만들기를 한 번 더 확인해보세요. |

### 7.5 학생에게 보여주지 않는 것과 교사에게 보여주는 것

진단 결과와 오개념 분석은 학생에게 바로 보여주지 않는다. 학생 화면은 문제 풀이 흐름에 집중하고, 분석 결과는 교사가 해석해서 수업이나 개별 지도에 활용하는 구조로 둔다.

학생에게 보여주지 않는 것:

- "너는 통분 개념이 부족해."
- "분모가 다른 분수를 더하는 원리를 이해하지 못했어."
- "공통분모 단계에서 오래 걸렸어."
- "오개념 가능성이 높아."

학생에게 보여줘도 되는 것:

- 풀이가 완료되었다는 안내
- 다음 문제로 넘어가는 버튼
- 교사가 설정한 경우의 중립적 힌트
- 진단 느낌이 없는 조작 안내

교사에게 보여줄 수 있는 것:

- 어느 단계에서 오래 머물렀는지에 대한 해석
- 선택 변경이나 되돌아가기 패턴
- 반복되는 오답 보기
- 예상되는 부족 개념
- 다음 수업에서 바로 쓸 수 있는 지도 제안

이 설계의 장점은 학생에게 낙인감을 주지 않으면서도, 교사가 학생의 사고 과정을 더 정확하게 볼 수 있다는 점이다.

### 7.6 학생 입력 방식 원칙

사용자가 지적한 것처럼, 초등학생에게 풀이 과정을 쓰게 하는 방식은 조심해야 한다. 학생이 수학 개념을 알고 있어도 문장으로 설명하는 데 부담을 느끼면 포기할 수 있다. 그러면 시스템은 수학 이해 부족이 아니라 국어 표현 부담을 수학 부족으로 잘못 해석할 위험이 있다.

따라서 MVP의 입력 원칙은 다음과 같이 잡는다.

> 수학 사고를 보기 위해 국어 능력을 과하게 요구하지 않는다.

내 의견으로는 `선택형 + 짧은 서술`보다 `조작형 + 선택형 + 최소 작성`이 더 좋은 출발점이다.

| 입력 방식 | 장점 | 위험 | MVP 적용 |
|---|---|---|---|
| 자유 서술 | 사고를 풍부하게 볼 수 있음 | 글쓰기 부담, 타자 부담, 포기 가능성 | 기본값으로 두지 않음 |
| 짧은 서술 | 이유를 확인할 수 있음 | 학생이 아는 것을 말로 못 쓸 수 있음 | 선택 사항으로 둠 |
| 선택형 이유 | 부담이 낮고 분석이 쉬움 | 보기 설계가 나쁘면 사고가 제한됨 | 적극 사용 |
| 조작형 입력 | 실제 풀이 과정을 행동 데이터로 볼 수 있음 | UI 설계가 필요함 | 핵심 방식으로 사용 |
| 음성 설명 | 말이 편한 학생에게 자연스러움 | 교실 환경, 녹음 부담, 분석 난이도 | 후순위 실험 |
| 손글씨/사진 | 실제 풀이와 가장 가까움 | 인식 정확도와 구현 난이도 높음 | 장기 확장 |

예를 들어 `1/2 + 1/3` 문제에서 학생에게 "왜 통분해야 하나요?"라고 쓰게 하기보다, 다음처럼 행동으로 보게 할 수 있다.

1. 학생이 `1/2`와 `1/3` 분수막대를 화면에 놓는다.
2. 시스템이 "바로 더할 수 있을까?"를 묻고, 학생이 선택한다.
3. 학생이 두 분수를 `6`조각 기준으로 바꾸는 조작을 한다.
4. 시스템이 "왜 이렇게 바꿨을까?"를 짧은 보기로 묻는다.

보기 예시:

- "조각의 크기를 같게 만들려고"
- "분자를 더 크게 만들려고"
- "분모와 분자를 모두 더하려고"
- "잘 모르겠어요"

이렇게 하면 학생이 긴 글을 쓰지 않아도 사고의 방향을 확인할 수 있다. 특히 오답 보기를 잘 설계하면 학생의 오개념을 더 선명하게 볼 수 있다.

짧은 서술은 완전히 버리지 않는다. 다만 모든 문제에 강제하지 않고, 다음 상황에서만 가볍게 요청한다.

- 답은 맞았지만 풀이 선택이 불안정할 때
- 시스템이 두 가지 오개념 후보 중 하나를 고르기 어려울 때
- 교사가 특정 학생의 설명 능력을 보고 싶을 때
- 학생이 직접 "설명해볼래" 활동을 선택했을 때

즉, 서술은 핵심 입력이 아니라 보조 진단 수단으로 둔다.

### 7.7 개념 분절 기반 진단 설계

사용자의 핵심 아이디어는 다음과 같다.

> 수학적인 개념을 최대한 분절해서, 아이들의 선택과 작성 하나하나가 진단 힌트가 되게 구성한다.

이 방향이 매우 중요하다. 시스템이 학생에게 "풀이 과정을 설명해봐"라고 크게 요구하면 학생은 막막해질 수 있다. 반대로 수학 개념을 작은 판단 단위로 쪼개면, 학생은 한 번에 하나의 선택만 하면 되고 시스템은 그 선택의 흔적을 모아 오개념을 추정할 수 있다.

핵심은 `긴 풀이 요구`가 아니라 `작은 판단의 연속`이다.

예를 들어 `1/2 + 1/3` 문제를 하나의 문제로만 보면 학생의 답은 `5/6` 또는 오답으로 끝난다. 하지만 개념을 분절하면 다음과 같은 관찰 지점이 생긴다.

| 분절된 판단 | 학생에게 주는 행동 | 진단 힌트 |
|---|---|---|
| 두 분수의 분모가 같은가? | "바로 더할 수 있을까?"를 선택 | 분모가 다르면 단위가 다르다는 인식 여부 |
| 같은 크기의 조각으로 바꿔야 하는가? | 이유 보기를 선택 | 통분의 목적 이해 여부 |
| 어떤 기준 조각으로 바꿀 것인가? | 분수막대에서 2칸, 3칸, 6칸 기준을 선택 | 공통분모와 최소공배수 감각 |
| `1/2`는 몇 조각이 되는가? | 분수막대에서 `3/6`을 만든다 | 동치분수 이해 |
| `1/3`은 몇 조각이 되는가? | 분수막대에서 `2/6`을 만든다 | 동치분수 이해 |
| 무엇끼리 더해야 하는가? | 같은 크기의 조각만 합친다 | 같은 단위끼리 더한다는 원리 |
| 최종 답을 어떻게 표현할 것인가? | `5/6`을 선택하거나 입력 | 계산 결과와 기호 표현 |

이렇게 나누면 학생이 마지막 답을 틀려도 교사는 어느 단계까지 이해했는지 볼 수 있다.

예를 들어 같은 `2/5` 오답이라도 원인이 다를 수 있다.

| 학생 행동 | 가능한 진단 |
|---|---|
| 처음부터 `분모와 분자를 각각 더한다`를 선택 | 분수 덧셈을 자연수 덧셈처럼 처리하는 오개념 |
| 통분해야 한다고 선택했지만 `1/2 -> 2/4`, `1/3 -> 2/6`을 만듦 | 공통 기준을 맞추는 개념이 불안정함 |
| `3/6`, `2/6`까지 만들고 마지막에 `5/12`를 선택 | 통분은 이해했지만 같은 단위끼리 더할 때 분모를 유지한다는 절차가 불안정함 |
| 정답은 맞지만 이유 선택에서 "분자를 더 크게 만들려고"를 고름 | 절차는 따라 했지만 통분의 의미 설명이 불안정함 |

여기서 학생의 `작성`은 긴 문장이 아니라 아주 작은 입력이면 충분하다.

- 보기 선택
- 숫자 한 칸 입력
- 분수막대 조각 수 선택
- 이전 단계로 돌아가기
- "잘 모르겠어요" 선택
- 이유 카드 선택
- 답 수정

이런 작은 행동들이 모두 교사용 리포트의 근거가 된다.

### 7.8 분수막대를 첫 조작 도구로 잡는 이유

첫 조작 도구는 분수막대로 정한다.

분수막대가 좋은 이유는 5학년 분수 MVP의 핵심인 약분, 통분, 분수 덧셈/뺄셈을 시각적으로 보여주기 좋기 때문이다. 특히 `같은 크기의 조각으로 바꾼다`는 통분의 의미를 말로 설명하지 않아도 행동으로 드러낼 수 있다.

분수막대로 관찰할 수 있는 것:

- 학생이 전체를 같은 길이로 보고 있는가?
- `1/2`와 `3/6`이 같은 양이라는 것을 이해하는가?
- 분모가 다른 조각을 바로 더하려고 하는가?
- 같은 크기의 조각으로 바꾼 뒤 더하는가?
- 분수막대를 조작한 뒤 기호식으로 연결할 수 있는가?
- 정답을 맞혀도 조작 과정이 안정적인가?

내 의견으로는 분수막대는 초반 MVP에서 `수학 개념을 시각화하는 도구`이면서 동시에 `학생 사고를 수집하는 센서` 역할을 할 수 있다.

### 7.8.1 분수막대 조작 방식

분수막대는 MVP에서 `직접 끌어다 놓기`보다 `기준/조각 수를 선택하면 자동 생성되는 방식`을 기본으로 한다.

예를 들어 학생이 `1/2`를 `6`조각 기준으로 바꾸는 단계에서는 조각을 하나씩 끌어다 놓게 하기보다, 다음처럼 선택하게 한다.

1. 기준 조각 수를 고른다. 예: `2`, `3`, `5`, `6`
2. `1/2`가 몇 조각이 되는지 고른다. 예: `2/6`, `3/6`, `4/6`
3. 시스템이 선택 결과를 분수막대로 자동 생성해 보여준다.
4. 학생은 생성된 막대가 맞는지 확인하고 다음 판단으로 넘어간다.

직접 끌어다 놓기가 줄 수 있는 추가 데이터는 분명히 있다.

- 어떤 조각을 먼저 잡는가
- 어디에 잘못 놓는가
- 몇 번 놓았다가 다시 빼는가
- 같은 위치에서 반복해서 실수하는가
- 조각을 배치한 순서가 안정적인가
- 시각적 모델을 스스로 구성할 수 있는가

하지만 MVP에서 이 방식은 진단을 흐릴 수 있다. 학생이 수학을 몰라서 틀린 것인지, 손가락 조작이 서툴러서 틀린 것인지, 화면 크기가 작아서 놓친 것인지 구분하기 어렵기 때문이다. 특히 초등학생은 기기 조작 능력 차이가 크기 때문에, 직접 조작 데이터가 곧바로 수학 이해 데이터라고 보기 어렵다.

따라서 MVP의 추천 방식은 다음과 같다.

| 방식 | MVP 판단 | 이유 |
|---|---|---|
| 조각 수 선택 후 자동 생성 | 기본 방식 | 수학 판단을 깨끗하게 수집하기 좋고 조작 부담이 낮음 |
| 직접 끌어다 놓기 | 후속 실험 | 행동 데이터는 풍부하지만 UI 조작 능력이 섞일 위험이 있음 |
| 자동 생성 + 일부 직접 수정 | 2차 후보 | 기본 진단 후, 특정 학생/문항에서만 더 깊게 볼 수 있음 |

나중에 직접 끌어다 놓기를 실험하려면, 먼저 짧은 연습 화면을 두어야 한다. 학생이 분수막대 조작법을 익혔는지 확인한 뒤에야 그 데이터를 수학 진단에 쓰는 것이 안전하다.

후속 실험 기준:

- 연습 화면에서는 잘 조작했는데 진단 문항에서만 틀리는가?
- 조작 실수와 개념 오류를 분리해 기록할 수 있는가?
- 직접 조작이 학생의 포기율을 높이지 않는가?
- 교사가 직접 조작 로그를 실제로 유용하다고 느끼는가?

### 7.9 한 번에 한 판단씩 넘기는 화면 원칙

학생 풀이 화면은 `한 번에 한 판단씩` 넘기는 방식으로 설계한다.

이 방식이 좋은 이유는 두 가지다.

첫째, 학생의 인지 부담이 낮아진다. 한 화면에 문제, 분수막대, 여러 선택지, 풀이 과정, 이유 입력, 피드백을 모두 보여주면 학생은 무엇을 해야 하는지 헷갈릴 수 있다. 반대로 한 화면에서 하나의 판단만 요구하면 학생은 지금 해야 할 일에만 집중할 수 있다.

둘째, 진단 데이터가 더 깨끗해진다. 여러 행동을 한 화면에서 동시에 하게 하면 학생이 어떤 개념 때문에 막혔는지 분리하기 어렵다. 하지만 한 번에 하나의 판단만 기록하면 각 선택이 하나의 진단 힌트가 된다.

예시 흐름:

| 화면 | 학생에게 묻는 것 | 학생 행동 | 수집되는 진단 신호 |
|---|---|---|---|
| 1 | `1/2`와 `1/3`을 바로 더할 수 있을까? | 가능/불가능 선택, 30초 후 모르겠음 선택 | 분모가 다르면 단위가 다르다는 인식 |
| 2 | 같은 크기의 조각으로 바꾸려면 몇 조각 기준이 좋을까? | 2, 3, 5, 6 중 선택 | 공통분모 감각 |
| 3 | `1/2`를 6조각 기준으로 바꿔보자. | 분수막대 변환 선택 | 동치분수 이해 |
| 4 | `1/3`을 6조각 기준으로 바꿔보자. | 분수막대 변환 선택 | 동치분수 이해 |
| 5 | 이제 몇 조각을 더해야 할까? | 조각 선택 | 같은 단위끼리 더한다는 원리 |
| 6 | 답을 고르자. | `5/6` 등 선택 | 기호 표현과 최종 계산 |

화면 설계 원칙:

- 한 화면에는 하나의 핵심 질문만 둔다.
- 이전 단계의 학생 선택은 작게 보여줘서 기억 부담을 줄인다.
- 이전 단계로 돌아가기를 허용하고, 되돌아간 위치와 수정 결과를 진단 힌트로 남긴다.
- "모르겠음"은 처음부터 고정 노출하지 않고, 30초 이상 머물렀을 때 나타나게 한다.
- 오답 선택지도 일부러 의미 있게 설계한다.
- 진행률은 숫자보다 작은 진행 막대로 보여줘서 학생이 얼마나 남았는지 알 수 있게 한다.

이 방식은 학생에게는 단순한 단계형 풀이처럼 보이지만, 교사에게는 개념 단위의 진단 기록으로 변환된다.

### 7.9.1 학생 화면 세부 UI 결정

학생 화면의 기본 이동 방식은 `다음으로 이동`과 `이전 단계로 돌아가기`를 모두 허용한다.

이전 단계로 돌아가기는 학생에게 안전한 수정 기회를 주고, 교사에게는 중요한 진단 신호가 된다. 예를 들어 학생이 공통분모 선택 단계로 돌아간 뒤 `5`를 `6`으로 고쳤다면, 처음 판단은 흔들렸지만 자기 수정이 가능한 상태로 볼 수 있다.

되돌아가기에서 수집할 데이터:

- 어느 단계에서 어느 단계로 돌아갔는가
- 돌아간 뒤 선택을 바꿨는가
- 바꾼 선택이 개념적으로 더 나아졌는가
- 돌아간 뒤 최종 정답에 도달했는가
- 같은 단계로 반복해서 돌아갔는가

교사용 해석 예시:

| 행동 로그 | 교사용 해석 |
|---|---|
| 2단계로 돌아가 공통 기준을 `5`에서 `6`으로 수정 | 통분 기준을 처음에는 혼동했지만 스스로 수정했습니다. |
| 3단계와 4단계를 반복해서 오감 | 동치분수 변환이 아직 안정적이지 않을 수 있습니다. |
| 되돌아가지 않고 빠르게 오답 선택 | 문제를 충분히 확인하지 않고 성급하게 판단했을 가능성이 있습니다. |

이전 단계 버튼은 화면 왼쪽 위에 작게 둔다. 화면에는 원형 버튼 안에 들어간 곡선 화살표 아이콘만 보여준다. 하단의 주요 행동 영역은 `다음`에 집중시키고, 이전 단계 이동은 보조 행동으로 분리한다. 다만 버튼 크기는 터치하기 어렵지 않게 최소 44px 터치 영역을 확보해야 하고, 실제 구현에서는 스크린리더용 접근성 라벨을 `이전 단계`로 제공해야 한다.

진행률은 화면 최상단 중앙에 둔다. `3/6단계` 같은 숫자를 붙이지 않고 작은 진행 막대만 보여준다. 단계 이름도 기본값으로는 붙이지 않는다. 학생에게 "몇 단계 남았다"는 압박보다 "조금씩 진행 중"이라는 감각만 주는 것이 목적이다. 다만 실제 구현에서는 접근성을 위해 화면 낭독용 텍스트로 현재 단계 정보를 제공하는 것이 좋다.

"잘 모르겠어요" 버튼은 처음부터 고정 노출하지 않는다. 학생이 30초 동안 선택하지 못하면 선택지 아래에 나타나게 한다. 이 버튼은 포기 버튼이 아니라, 학생이 막힌 지점을 알려주는 안전한 출구로 설계한다. `다음` 버튼과 같은 위계로 보이면 안 되므로 보조 버튼처럼 차분하게 둔다.

"잘 모르겠어요"를 선택하면 즉시 힌트를 주지 않고 다음 단계로 넘어간다. 진단형 문제에서는 바로 힌트를 주는 순간 이후 단계의 이해도를 관찰하기 어려워질 수 있기 때문이다. 대신 다음 단계가 이전 답에 의존한다면, 시스템이 필요한 최소 기준만 중립적으로 제공한다.

예시:

| 학생 행동 | 다음 화면 처리 |
|---|---|
| 공통 기준 선택에서 "모르겠음" 선택 | "이번에는 6조각 기준으로 바꿔볼게."처럼 기준만 제공하고 동치분수 판단을 계속 관찰 |
| `1/2`를 `3/6`으로 바꾸는 단계에서 "모르겠음" 선택 | `1/2 = 3/6`을 보여준 뒤, `1/3` 변환 단계로 이동 |
| 마지막 답 선택에서 "모르겠음" 선택 | 문제를 종료하고 교사용 리포트에 마지막 표현 단계에서 막힘으로 기록 |

"모르겠음" 관련 수집 데이터:

- 버튼이 나타나기 전까지 머문 시간
- 버튼이 나타난 뒤 바로 눌렀는지 여부
- 버튼이 나타난 뒤에도 스스로 선택했는지 여부
- "모르겠음" 선택 이후 다음 단계에서 회복했는지 여부
- "모르겠음" 이후 제공된 최소 기준이 무엇이었는지

주의할 점은 `모르겠음`을 늦게 보여주는 방식이 학생을 압박하는 타이머처럼 느껴지면 안 된다는 것이다. 화면에는 초시계를 보여주지 않고, 30초 후 조용히 보조 선택지가 나타나는 방식이 좋다.

이때 제공되는 문장은 힌트처럼 설명하지 않고, 다음 활동을 가능하게 하는 중립 발판이어야 한다.

| 피해야 할 문장 | 더 나은 문장 |
|---|---|
| "분모가 다르니까 6으로 통분해야 해." | "이번에는 6조각 기준으로 이어가 볼게." |
| "1/2는 3/6이야. 이렇게 해야 맞아." | "`1/2 = 3/6`으로 두고 다음을 해보자." |
| "틀렸으니 다시 생각해봐." | "이 단계는 잠시 넘기고 다음 판단을 해보자." |

학생이 선택지를 고른 뒤에는 자동으로 다음 화면으로 넘어가지 않는다. 반드시 `다음` 버튼을 눌러 넘어간다. 선택 전에는 `다음` 버튼을 비활성화한다. 이 방식은 불필요한 오류 메시지를 줄이고, 한 번 더 확인할 여유를 주며, 선택 직후 마음을 바꾸는 행동을 데이터로 남길 수 있다.

활성화된 `다음` 버튼은 차분하지만 명확하게 보이는 주 버튼으로 둔다. 너무 강한 색이나 과한 애니메이션으로 학생을 재촉하지 않는다. 선택 전 비활성 상태는 흐린 회색 계열처럼 명확히 눌릴 수 없게 보이되, 텍스트 대비는 읽을 수 있게 유지한다.

학생이 틀렸을 때는 화면에서 강한 빨간색 피드백을 바로 보여주지 않는다. 이 제품의 학생 화면은 즉시 채점 화면이 아니라 과정 수집 화면이므로, 학생에게 틀렸다는 감각을 강하게 주기보다 다음 판단으로 자연스럽게 이어가는 편이 좋다. 오답과 오개념 해석은 교사용 리포트에서 다룬다.

선택 후 `다음` 버튼 대기에서 수집할 데이터:

- 첫 선택 후 `다음`을 누르기까지 걸린 시간
- `다음`을 누르기 전에 선택을 바꿨는지 여부
- 선택을 바꾼 횟수
- 선택 후 이전 단계로 돌아갔는지 여부

교사용 해석 예시:

| 행동 로그 | 교사용 해석 |
|---|---|
| 선택 후 바로 `다음` 클릭, 반복 정답 | 해당 판단이 안정적일 가능성이 높습니다. |
| 선택 후 오래 머물다가 선택 변경 | 개념 판단에 확신이 부족할 수 있습니다. |
| 선택 후 이전 단계로 돌아감 | 앞 단계 선택을 다시 확인해야 한다고 느꼈을 수 있습니다. |

### 7.10 기본 6단계와 유동 단계 수

한 문제는 기본적으로 6단계로 분절한다. 다만 6단계는 고정 규칙이 아니라 기본 템플릿이다. 문제의 난이도, 진단 목적, 학생 수준에 따라 4~8단계 정도로 조정할 수 있어야 한다.

기본 6단계가 좋은 이유:

- 학생이 지치기 전에 끝낼 수 있다.
- 한 단계당 하나의 판단만 담기 좋다.
- 교사가 보기에도 진단 로그가 너무 길어지지 않는다.
- 통분, 변환, 계산, 답 선택까지 핵심 개념을 충분히 나눌 수 있다.

단계 수 원칙:

| 단계 수 | 적합한 문제 | 사용 목적 |
|---:|---|---|
| 3~4단계 | 이미 배운 개념을 빠르게 확인하는 문제 | 가벼운 체크, 복습 |
| 5~6단계 | 핵심 진단 문제 | MVP 기본값 |
| 7~8단계 | 문장제, 복합 개념 문제 | 깊은 진단 |
| 9단계 이상 | 한 문제로는 부담이 큰 경우 | 문제를 둘로 나누는 편이 좋음 |

5학년 분수 덧셈 기본 6단계 템플릿:

| 단계 | 핵심 판단 | 예시 질문 | 진단 포인트 |
|---:|---|---|---|
| 1 | 바로 계산 가능한가? | `1/2`와 `1/3`을 바로 더할 수 있을까? | 분모가 다르면 단위가 다르다는 인식 |
| 2 | 어떤 공통 기준을 쓸 것인가? | 몇 조각 기준으로 바꾸면 좋을까? | 공통분모 감각 |
| 3 | 첫 번째 분수를 바꿀 수 있는가? | `1/2`를 6조각 기준으로 바꿔보자. | 동치분수 이해 |
| 4 | 두 번째 분수를 바꿀 수 있는가? | `1/3`을 6조각 기준으로 바꿔보자. | 동치분수 이해 |
| 5 | 무엇을 더해야 하는가? | 이제 몇 조각과 몇 조각을 더할까? | 같은 단위끼리 더한다는 원리 |
| 6 | 답을 표현할 수 있는가? | 답을 고르자. | 최종 계산과 기호 표현 |

유동적으로 바꾸는 예:

- 쉬운 복습 문제: 4단계로 줄인다.
- 처음 진단하는 핵심 문제: 6단계로 둔다.
- 문장제처럼 전체 기준을 먼저 찾아야 하는 문제: 앞에 `전체가 무엇인가?` 단계를 추가해 7단계로 만든다.
- 학생이 이미 안정적인 개념을 보이는 경우: 중간 조작 단계를 줄이고 바로 이유 선택으로 넘어간다.

문제 데이터에는 단계 수를 고정 값으로 박아두기보다, 각 문제마다 `기본 단계`, `생략 가능한 단계`, `추가 진단 단계`를 설정할 수 있게 하는 편이 좋다.

초기 MVP에서는 학생이 이미 잘하는 것처럼 보이는 단계도 자동으로 건너뛰지 않는다. 아직 데이터가 충분하지 않은 상태에서 단계를 생략하면, 교사가 봐야 할 중요한 진단 힌트를 놓칠 수 있기 때문이다.

단계 생략 정책은 다음처럼 단계적으로 가져간다.

| 시기 | 단계 운영 | 이유 |
|---|---|---|
| MVP 초기 | 6단계를 모두 확인 | 학생별 기준 데이터 확보, 진단 정확도 우선 |
| 데이터 축적 이후 | 반복적으로 안정적인 단계는 일부 생략 | 학생 부담 감소 |
| 개인화 단계 | 학생별로 필요한 단계만 노출 | 효율과 진단 정확도 균형 |

즉, 초반에는 `정확한 진단 데이터 수집`을 우선하고, 이후에는 `학생 부담 감소`를 위해 적응형 생략을 도입한다.

### 7.11 단계별 시간 데이터

단계별 소요 시간은 매우 중요한 진단 데이터다. 같은 오답이라도 어느 단계에서 오래 머물렀는지에 따라 원인 해석이 달라질 수 있다.

예를 들어 6단계 분수 덧셈 문제에서 학생이 오래 머무는 위치는 다음처럼 해석할 수 있다.

| 오래 머문 단계 | 가능한 의미 | 추가로 같이 봐야 할 데이터 |
|---|---|---|
| 1. 바로 계산 가능한가? | 분모가 다르면 바로 더할 수 없다는 개념이 불안정함 | 선택 변경, "모르겠음" 선택 여부 |
| 2. 공통 기준 선택 | 공통분모 또는 최소공배수 감각이 약함 | 고른 기준 조각, 수정 횟수 |
| 3~4. 동치분수 만들기 | `1/2 = 3/6` 같은 변환 이해가 약함 | 분수막대 변환 선택 오류, 되돌아가기 |
| 5. 무엇을 더할지 선택 | 같은 단위끼리 더한다는 원리가 불안정함 | 분모까지 더하려는 선택 여부 |
| 6. 답 표현 | 조작은 이해했지만 기호식 표현이 약함 | 최종 답 오류, 숫자 입력 수정 |

시간 데이터는 단독으로 "이해 부족"이라고 판단하면 위험하다. 학생이 신중해서 오래 걸렸을 수도 있고, UI 조작이 낯설어서 오래 걸렸을 수도 있다. 따라서 시간은 항상 다른 행동 데이터와 함께 해석해야 한다.

시간 데이터를 해석하는 기본 원칙:

- `오래 걸림 + 정답 + 수정 많음`: 개념은 도달했지만 안정성이 낮을 수 있다.
- `오래 걸림 + 오답 + 모르겠음`: 해당 단계 개념 보충이 필요할 가능성이 높다.
- `짧은 시간 + 오답`: 찍기, 성급한 판단, 문제 이해 부족 가능성이 있다.
- `짧은 시간 + 반복 정답`: 숙련된 개념일 가능성이 있다.
- `힌트 이후 시간 감소`: 힌트가 실제로 도움이 되었는지 볼 수 있다.
- `되돌아간 뒤 정답`: 자기 수정 능력은 있지만 초기 판단이 불안정할 수 있다.

수집하면 좋은 시간 관련 지표:

| 지표 | 설명 | 활용 |
|---|---|---|
| 단계별 소요 시간 | 각 판단 화면에서 머문 시간 | 어느 개념에서 멈췄는지 확인 |
| 첫 선택까지 걸린 시간 | 화면 진입 후 처음 선택하기까지의 시간 | 망설임, 이해 난이도 추정 |
| 선택 변경 횟수 | 같은 화면에서 답을 바꾼 횟수 | 확신 부족 또는 자기 수정 |
| 되돌아간 단계 | 이전 단계로 돌아간 위치 | 어느 판단을 다시 확인했는지 파악 |
| 힌트 요청까지 걸린 시간 | 막힌 뒤 힌트를 누르기까지의 시간 | 도움 요청 성향, 끈기 |
| 힌트 후 수정 시간 | 힌트 이후 다시 답하기까지의 시간 | 힌트 효과 추정 |

교사 리포트에서는 "오래 걸렸다"만 보여주면 안 된다. 다음처럼 해석 가능한 문장으로 바꿔야 한다.

- "공통분모를 고르는 단계에서 시간이 길고 선택 변경이 많았습니다."
- "분수막대 변환 선택은 안정적이지만, 마지막 기호식 표현에서 시간이 오래 걸렸습니다."
- "힌트 후 같은 단위끼리 더해야 한다는 선택으로 수정했습니다."

이런 시간 데이터는 교사가 학생에게 "너는 느려"라고 말하게 만드는 데이터가 아니라, "어느 생각에서 오래 고민했는지"를 찾는 데이터여야 한다.

교사 화면에는 초 단위 원자료를 기본값으로 그대로 노출하지 않는다. 대신 아래처럼 해석된 신호로 보여주는 것이 좋다.

| 원자료 | 교사용 표현 |
|---|---|
| 2단계 체류 시간 48초, 선택 변경 3회 | 공통 기준을 고르는 단계에서 고민이 많았습니다. |
| 5단계 체류 시간 8초, 오답 선택 | 같은 단위끼리 더하는 단계를 빠르게 지나가며 오류가 발생했습니다. |
| 3단계 되돌아가기 2회, 최종 정답 | 동치분수 변환을 스스로 수정해 정답에 도달했습니다. |

### 7.12 시간 외에 수집할 수 있는 행동 데이터

시간은 중요한 데이터지만, 시간만으로는 부족하다. 학생이 오래 고민했는지, 찍었는지, UI 조작에 막혔는지, 스스로 수정했는지를 구분하려면 다른 행동 데이터도 함께 수집해야 한다.

수집하면 좋은 데이터:

| 데이터 | 의미 | 진단 활용 |
|---|---|---|
| 첫 선택까지 걸린 시간 | 처음 판단까지의 망설임 | 개념 인식 난이도 |
| 선택 변경 횟수 | 답을 바꾼 횟수 | 확신 부족, 자기 수정 |
| 되돌아간 단계 | 이전 화면으로 돌아간 위치 | 다시 확인한 개념 |
| 분수막대 생성 시도 횟수 | 기준/조각 수를 고르고 다시 바꾼 횟수 | 시각적 모델 이해도 |
| 잘못 선택한 기준/조각 수 | 틀리게 만든 분수막대 표현 | 분모/분자 또는 동치분수 이해 |
| "모르겠음" 선택 위치 | 막힌 단계 | 직접적인 취약 단계 후보 |
| 힌트 요청 위치 | 도움을 요청한 단계 | 교사 개입 필요 지점 |
| 힌트 후 수정 여부 | 힌트 이후 바뀐 행동 | 힌트 효과, 학습 가능성 |
| 오답 보기 선택 | 어떤 오답을 골랐는지 | 특정 오개념 후보 |
| 같은 개념 반복 오류 | 여러 문제에서 반복되는 패턴 | 주요 부족 개념 확정 |

예를 들어 `시간이 오래 걸림`은 다음처럼 다른 의미를 가질 수 있다.

- 오래 걸렸지만 선택 변경 없이 정답: 신중한 학생일 수 있다.
- 오래 걸리고 선택 변경이 많음: 개념이 불안정할 수 있다.
- 오래 걸리고 "모르겠음" 선택: 해당 단계에서 직접 막혔을 수 있다.
- 짧게 보고 오답: 찍었거나 판단을 성급하게 했을 수 있다.
- 되돌아간 뒤 정답: 초기 판단은 불안정하지만 자기 수정 능력이 있다.

따라서 교사용 리포트는 단일 데이터가 아니라 `시간 + 선택 변경 + 되돌아가기 + 오답 유형 + 힌트 반응`을 묶어서 해석해야 한다.

### 7.13 DeepSeek API 사용 판단

AI API는 DeepSeek을 사용한다.

내 판단으로는 DeepSeek API를 처음부터 모든 채점과 진단에 쓰는 것은 좋지 않다. 특히 5학년 분수 MVP의 핵심 판단은 선택형, 조작형, 단계별 로그로 꽤 많이 구조화할 수 있다. 이 부분은 규칙 기반으로 처리하는 편이 더 안정적이고 설명 가능하다.

다만 DeepSeek API가 유용한 영역은 분명히 있다. 핵심은 `정답 판정`보다 `교사용 해석과 설명`이다.

| 영역 | DeepSeek API 필요도 | 이유 |
|---|---|---|
| 최종 정답 판정 | 낮음 | 분수 계산은 규칙 기반으로 정확히 판정 가능 |
| 단계별 선택 판정 | 낮음~중간 | 보기와 조작 로그가 구조화되어 있으면 규칙 기반 가능 |
| 분수막대 변환 선택 오류 탐지 | 낮음~중간 | 기준/조각 수 선택 로그로 판정 가능 |
| 짧은 서술 해석 | 중간 | 개인정보 가능성이 있어 MVP에서는 비식별 처리된 짧은 표현만 제한적으로 사용 |
| 오개념 후보 요약 | 중간~높음 | 여러 행동 로그를 교사가 이해할 수 있게 요약해야 함 |
| 교사용 피드백 문장 생성 | 높음 | 같은 데이터도 교사가 바로 쓰기 좋은 문장으로 바꿔야 함 |
| 학생용 중립 안내 문장 생성 | 낮음~중간 | MVP에서는 학생에게 진단을 보여주지 않으므로, 조작 방법 안내 정도로 제한 |
| 문제/단계 초안 생성 | 중간 | 교사가 검토한다는 전제에서 생산성 향상 가능 |
| 장기 학습 리포트 | 높음 | 여러 문제의 패턴을 종합하는 데 유용 |

초기 MVP의 추천 구조:

- 규칙 기반 엔진: 정답, 단계별 선택, 분수막대 조작, 시간 로그, 오답 패턴을 우선 판정한다.
- DeepSeek API: 익명화된 요약 로그를 바탕으로 교사용 요약, 추천 지도 문장, 애매한 패턴 해석을 담당한다.
- 교사 검토: DeepSeek이 만든 진단 문장이나 추천 지도는 교사가 수정할 수 있게 한다.

DeepSeek 전송 원칙:

> DeepSeek에는 개인정보를 보내지 않는다. 외부 AI API에는 익명화된 요약 로그만 보낸다.

보내도 되는 데이터:

- 익명 세션 ID
- 문제 ID
- 개념 태그
- 단계별 성공/오류 여부
- 선택 변경 횟수
- 되돌아가기 횟수
- 시간 해석 신호
- 오답 유형 코드
- 힌트 요청 여부
- 규칙 기반 엔진이 만든 오개념 후보

보내면 안 되는 데이터:

- 학생 이름
- 학교명
- 반 이름
- 출석번호처럼 개인을 좁힐 수 있는 식별자
- 전화번호, 이메일, 보호자 정보
- IP, 기기 식별자 같은 기술 식별 정보
- 학생이 쓴 자유 문장 원문 중 개인정보가 섞일 가능성이 있는 내용
- 교사가 남긴 민감한 개별 메모 원문

내 의견으로는 MVP에서는 자유 서술 원문을 DeepSeek에 보내지 않는 편이 좋다. 정말 필요하다면 서버 내부에서 먼저 개인정보 포함 가능성을 검사하고, 수학적 의미만 짧게 요약한 뒤 보내야 한다.

DeepSeek API를 쓰면 좋은 예:

```text
입력 데이터(익명화된 요약 로그):
- 문제: 1/2 + 1/3
- 단계 1: 바로 더할 수 없다고 선택
- 단계 2: 공통 기준 5를 선택했다가 6으로 수정
- 단계 3: 1/2 -> 3/6 성공
- 단계 4: 1/3 -> 2/6 성공
- 단계 5: 3 + 2 선택
- 단계 6: 5/12 선택

DeepSeek이 생성할 수 있는 교사용 요약:
학생은 통분 과정까지는 이해했지만, 마지막 답 표현에서 분모를 유지해야 한다는 절차가 불안정합니다. 같은 크기의 조각끼리 더할 때 조각의 크기는 그대로 유지된다는 활동을 추가하면 좋습니다.
```

DeepSeek API를 쓰지 않아도 되는 예:

- `1/2 + 1/3 = 5/6` 정답 판정
- `1/2 -> 3/6` 동치분수 판정
- 학생이 2, 3, 5, 6 중 어떤 공통 기준을 선택했는지 기록
- 각 단계별 소요 시간 계산
- 힌트 요청 여부 기록

중요한 원칙:

> DeepSeek은 진단의 주체라기보다, 구조화된 진단 데이터를 교사가 이해하고 지도에 활용할 수 있는 문장으로 번역하는 역할부터 시작한다.

장기적으로는 DeepSeek이 학생의 누적 패턴을 분석해 "이 학생은 통분보다 동치분수 개념에서 반복적으로 흔들린다" 같은 요약을 만들 수 있다. 하지만 MVP 초반에는 규칙 기반 진단을 먼저 단단히 만들고, DeepSeek API는 교사용 요약 생성과 애매한 입력 해석에 제한적으로 쓰는 편이 안전하다.

실제 구현 전에는 DeepSeek 공식 문서에서 최신 모델명, API 형식, 비용, 데이터 처리 조건을 확인해야 한다.

### 7.14 최소 작성 입력 설명

"최소 작성 입력"은 학생에게 긴 설명문을 쓰게 하자는 뜻이 아니다. 학생이 수학은 알고 있지만 글쓰기나 타자 때문에 포기하는 일을 막기 위해, 작성 부담을 아주 작게 줄인 입력 방식을 말한다.

예시:

| 입력 방식 | 예시 | 학생 부담 |
|---|---|---|
| 숫자 입력 | `6`, `3/6`, `5/6` | 낮음 |
| 기호 선택 | `>`, `<`, `=` 선택 | 낮음 |
| 이유 카드 선택 | "조각 크기를 같게 만들려고" 선택 | 낮음 |
| 짧은 단어 입력 | "통분", "같은 조각" | 중간 |
| 짧은 문장 입력 | "분모를 같게 해야 해서" | 높음 |
| 자유 서술 | 풀이 이유를 직접 문장으로 설명 | 매우 높음 |

MVP에서는 숫자/기호 입력과 이유 카드 선택을 기본으로 두고, 짧은 문장 입력은 선택 사항으로만 열어두는 것이 좋다.

즉, 학생에게 요구하는 작성은 `긴 설명`이 아니라 `진단에 필요한 최소 신호`다.

### 7.15 첫 진단 문항 세트

첫 진단 문항 세트는 5학년 분수 10문제로 시작한다.

10문제가 좋은 이유:

- 학생이 한 번에 풀기에 부담이 크지 않다.
- 6단계 구조를 적용해도 전체 풀이 시간이 너무 길어지지 않는다.
- 교사가 한 학생의 주요 오개념을 처음 파악하기에 충분한 신호를 얻을 수 있다.
- 문항별 개념 태그를 설계하기 쉽다.

초기 10문항 구성안:

| 문항 수 | 영역 | 확인하려는 것 |
|---:|---|---|
| 2문항 | 동치분수 | 같은 양을 다른 분수로 표현할 수 있는가 |
| 2문항 | 통분 | 공통 기준 조각을 찾을 수 있는가 |
| 3문항 | 분모가 다른 분수 덧셈 | 같은 단위끼리 더한다는 원리를 이해하는가 |
| 2문항 | 분모가 다른 분수 뺄셈 | 같은 단위끼리 빼는 원리를 이해하는가 |
| 1문항 | 짧은 문장제 | 전체 기준을 파악하고 식으로 연결할 수 있는가 |

첫 10문항 실제 초안:

| 번호 | 문제 | 핵심 진단 | 주요 오답 신호 |
|---:|---|---|---|
| 1 | `1/2`와 같은 크기의 분수를 고르시오. 보기: `2/4`, `2/3`, `1/4`, `3/4` | 동치분수의 의미 | 분자만 같거나 분모만 큰 분수를 고름 |
| 2 | `2/3 = ?/9`에서 `?`에 들어갈 수를 고르시오. | 분자와 분모에 같은 배 적용 | 분모만 9로 바꾸고 분자를 그대로 둠 |
| 3 | `1/2`와 `1/3`을 같은 크기 조각으로 바꾸려면 몇 조각 기준이 좋을까? | 공통분모 선택 | `5`처럼 분모를 더한 값을 고름 |
| 4 | `3/4`와 `5/6`을 같은 분모로 바꾸려면 어떤 기준이 좋을까? | 최소공배수 기반 통분 | `10`처럼 분모를 더하거나 더 작은 기준 `12`를 찾지 못함 |
| 5 | `1/2 + 1/3`을 계산하시오. | 통분 후 같은 단위끼리 더하기 | `2/5`, `5/12` 선택 |
| 6 | `2/3 + 1/6`을 계산하시오. | 한 분모가 다른 분모의 배수일 때 통분 | `3/9`, `3/6` 선택 |
| 7 | `3/4 + 1/8`을 계산하시오. | 동치분수 변환 후 덧셈 | `4/12`, `7/8` 선택 |
| 8 | `5/6 - 1/3`을 계산하시오. | 통분 후 같은 단위끼리 빼기 | `4/3`, `4/6` 선택 |
| 9 | `3/4 - 1/6`을 계산하시오. | 공통분모 선택과 뺄셈 절차 | `2/10`, `8/12` 선택 |
| 10 | 리본 `2/3m` 중에서 `1/4m`를 썼습니다. 남은 리본은 몇 m인가요? | 문장 상황을 분수 뺄셈으로 연결 | 전체 기준을 놓치거나 `1/7`처럼 분자/분모를 따로 계산 |

이 10문항은 처음부터 난도를 높이기보다 `동치분수 -> 통분 -> 덧셈/뺄셈 -> 문장제 연결` 순서로 배치한다. 앞 문항에서 흔들린 개념이 뒤 문항의 오류로 이어지는지 관찰할 수 있기 때문이다.

이 순서는 현재 MVP의 기본 순서로 확정한다.

각 문항은 모두 6단계로 고정하지 않는다. 1~2번은 4~5단계로 짧게 만들고, 5번 이후의 핵심 연산 문항은 6단계로 두는 편이 좋다. 10번 문장제는 문제 이해 단계가 필요하므로 7단계까지 늘릴 수 있다.

MVP 초기에는 10문항을 모두 같은 난이도로 만들기보다, 쉬운 확인 문제와 핵심 진단 문제를 섞는 편이 좋다.

## 8. 진단 결과 예시

초기 MVP에서는 5학년 분수 문제를 기준으로 진단 예시를 만든다.

### 8.1 분모가 다른 분수의 덧셈

예시 문제:

> `1/2 + 1/3`을 계산하시오.

가능한 풀이 단계:

1. 두 분수의 분모가 다르다는 것을 확인한다.
2. 공통분모 `6`을 찾는다.
3. `1/2`를 `3/6`으로 바꾼다.
4. `1/3`을 `2/6`으로 바꾼다.
5. `3/6 + 2/6 = 5/6`으로 계산한다.

진단 예시:

| 학생 풀이 | 최종 답 | 진단 |
|---|---:|---|
| `1/2 + 1/3 = 2/5` | `2/5` | 분모가 다른 분수를 같은 단위로 바꿔야 한다는 개념이 부족함 |
| `1/2 = 2/4`, `1/3 = 2/6`, `4/10` | `4/10` | 공통분모 선택과 동치분수 변환이 불안정함 |
| `1/2 = 3/6`, `1/3 = 2/6`, `5/12` | `5/12` | 통분은 했지만 마지막 덧셈에서 분모를 다시 더하는 절차 오류 |
| `1/2 = 3/6`, `1/3 = 2/6`, `5/6` | `5/6` | 통분과 덧셈 절차가 안정적임 |

이 문제 하나만 봐도 오답의 원인이 여러 갈래로 나뉜다. 따라서 시스템은 최종 답만 보지 말고, 학생이 어느 단계까지 올바르게 진행했는지를 봐야 한다.

### 8.2 분수 크기 비교

예시 문제:

> `3/4`와 `5/8` 중 어느 분수가 더 큰지 비교하시오.

가능한 풀이 단계:

1. 두 분수의 전체 기준이 같다고 본다.
2. 두 분수를 같은 분모로 바꿀 수 있는지 확인한다.
3. `3/4`를 `6/8`로 바꾼다.
4. `6/8`과 `5/8`을 비교한다.
5. `3/4`가 더 크다고 판단한다.

진단 예시:

| 학생 풀이 | 최종 답 | 진단 |
|---|---:|---|
| `5가 3보다 크니까 5/8이 더 크다` | `5/8` | 분자만 보고 크기를 비교하는 오개념 |
| `8이 4보다 크니까 5/8이 더 크다` | `5/8` | 분모가 클수록 분수가 크다고 보는 오개념 |
| `3/4 = 6/8`, `6/8 > 5/8` | `3/4` | 동치분수와 크기 비교가 안정적임 |
| 그림으로는 `3/4`를 고르지만 설명을 못함 | `3/4` | 직관은 있으나 수식 표현과 설명 능력이 부족함 |

이런 식으로 같은 5학년 분수 문제에서도 오류 위치를 다르게 분석할 수 있어야 한다.

## 9. 확장 방향

### 9.1 오개념 지도

각 문제를 단원, 개념, 선행 개념에 연결한다. 학생의 오류가 쌓이면 `오개념 지도`를 만들 수 있다.

예를 들어 분수 덧셈을 어려워하는 학생의 실제 원인이 통분 절차, 동치분수 이해, 최소공배수 개념, 같은 단위끼리 더한다는 원리 중 어디에 있는지 추적한다.

### 9.2 개인별 복습 경로

진단 결과를 바탕으로 다음 학습 경로를 자동 추천한다.

- 바로 다음 유형으로 넘어가도 되는 학생
- 같은 개념의 쉬운 문제를 더 풀어야 하는 학생
- 선행 개념으로 돌아가야 하는 학생
- 계산 연습만 짧게 보강하면 되는 학생

### 9.3 교사용 개입 제안

교사에게 단순 리포트만 주는 것이 아니라 수업 개입 방법을 제안한다.

- "이 학생은 문장제에서 전체 기준을 놓치므로, 먼저 그림으로 전체와 부분을 표시하게 해보세요."
- "이 그룹은 계산보다 통분의 의미에서 오류가 많으므로, 먼저 같은 크기의 조각으로 바꾸는 시각 활동을 진행하는 것이 좋습니다."

### 9.4 과정 기반 평가

장기적으로는 최종 답 중심 평가에서 과정 중심 평가로 확장할 수 있다.

- 풀이 전략 점수
- 식 세우기 점수
- 계산 정확도
- 검산 습관
- 개념 설명 능력

이렇게 되면 학생의 성장을 더 입체적으로 볼 수 있다.

## 10. 기술적으로 생각해볼 구성

초기 시스템은 다음 구성으로 볼 수 있다.

- 문제 데이터베이스: 문제, 정답, 풀이 단계, 개념 태그, 선행 개념 태그
- 학생 풀이 수집기: 단계별 입력, 시간, 수정 이력, 힌트 사용 기록
- 풀이 분석 엔진: 정답 여부, 단계별 오류, 오개념 후보 추정
- 리포트 생성기: 교사용 진단 설명, 학부모용 요약, 학생용 중립 안내 생성
- 추천 엔진: 다음 문제, 복습 개념, 보충 자료 추천

AI는 처음부터 모든 판단을 맡기기보다, 규칙 기반 분석과 함께 쓰는 것이 안전해 보인다.

- 규칙 기반: 명확한 계산 오류, 정답 비교, 단계 누락 탐지
- AI 기반: 익명화된 요약 로그 기반 오개념 설명, 교사용 피드백 문장 생성
- 교사 검토: 애매한 진단은 교사가 확인하거나 수정 가능하게 함

## 11. 지금 단계에서의 중요한 리스크

### 학생 입력 부담

풀이 과정을 자세히 받으려 할수록 학생은 귀찮아할 수 있다. 따라서 모든 문제를 단계 입력형으로 만들기보다, 진단이 필요한 문제에만 적용하는 설계가 필요하다.

### AI 진단의 신뢰성

학생의 풀이를 잘못 해석하면 교사와 학부모의 신뢰를 잃을 수 있다. 초반에는 "확정 진단"보다 "가능성이 높은 오류 후보"로 표현하는 것이 안전하다.

### 수학 교육과정 매핑

오개념 분석을 하려면 문제마다 개념 태그와 선행 개념 구조가 필요하다. 이 데이터 설계가 제품의 핵심 자산이 될 가능성이 높다.

### 교사의 실제 사용성

교사가 리포트를 읽는 데 시간이 오래 걸리면 쓰지 않을 수 있다. 한 반 전체를 빠르게 스캔할 수 있는 요약 화면이 중요하다.

### 12.8 UI/디자인 질문

하던 제품/데이터 질문을 정리한 뒤에는 UI와 디자인을 별도로 다뤄야 한다. 다만 버튼 모양, 버튼 위치, 색의 강도 같은 미시 UI 결정은 매번 사용자에게 묻지 않고 기본안을 정해 진행한다. 사용자에게 물어볼 질문은 학습 흐름, 진단 방식, 교사 리포트처럼 제품 방향이 달라지는 결정으로 제한한다.

학생 화면에서 이미 정한 기본안:

1. 한 화면에는 하나의 판단만 둔다.
2. 이전 단계는 왼쪽 위 원형 버튼 안의 곡선 화살표 아이콘으로 둔다.
3. 진행 막대는 화면 최상단 중앙에 두고, 단계 이름과 숫자는 숨긴다.
4. "잘 모르겠어요"는 30초 후 선택지 아래에 나타난다.
5. 선택지를 고른 뒤 자동 이동하지 않고 `다음` 버튼을 누르게 한다.
6. `다음` 버튼은 선택 전 비활성화, 선택 후 차분하지만 명확한 주 버튼으로 활성화한다.
7. 학생 화면에서는 강한 빨간색 오답 피드백을 바로 보여주지 않는다.

학생 화면에서 아직 남은 큰 질문:

1. 10문항 각각을 실제 4~7단계 화면으로 어떻게 쪼갤까?
2. 각 단계에서 숫자 입력, 이유 카드, 분수막대 생성 중 무엇을 먼저 둘까?
3. "잘 모르겠어요" 이후 제공할 중립 발판 문구를 문항별로 어떻게 만들까?
4. 학생 화면과 교사용 리포트가 같은 로그를 어떻게 다르게 해석하게 할까?

교사 화면 질문:

1. `반 전체 오개념 요약` 안에서 어떤 오개념을 가장 위에 올릴까?
2. 교사가 30초 안에 봐야 하는 정보는 무엇인가?
3. 오개념은 표, 카드, 태그, 그래프 중 어떤 형태가 가장 이해하기 쉬울까?
4. 시간 해석 신호는 색으로만 표시하지 않고 어떤 문장/아이콘과 함께 보여줄까?
5. 학생별 상세 화면에서 원본 풀이 로그를 얼마나 접어둘까?
6. 교사가 AI 요약을 수정하는 UI는 간단한 문장 편집이 좋을까, "맞음/수정/숨김" 같은 빠른 버튼이 좋을까?

디자인 원칙 후보:

- 학생 화면은 한 번에 한 판단만 요구한다.
- 교사 화면은 30초 안에 반 전체 흐름을 파악하게 한다.
- 교사 첫 화면은 반 전체 오개념 요약을 먼저 보여준다.
- 분수막대는 MVP에서 자동 생성 방식으로 시작한다.
- 이전 단계 이동은 허용하고, 교사용 진단 데이터로 기록한다.
- 진행률은 작은 진행 막대로 보여준다.
- "모르겠음" 버튼은 30초 후 조용히 나타나게 한다.

- 학생용 기능과 교사용 기능을 분리해서 생각해야 한다. 학생은 문제를 풀고 필요한 중립적 안내만 받는 사람이고, 교사는 그 데이터를 해석해서 가르치는 사람이다.
- 초등 분수에서는 `정답 여부`보다 `전체 기준을 잡았는지`, `같은 단위로 만들었는지`, `분모와 분자의 의미를 이해했는지`가 더 중요한 진단 포인트가 될 수 있다.
- 교사 화면은 "학생 A는 분수가 약합니다"가 아니라 "학생 A는 분모가 다른 분수를 더할 때 같은 단위로 바꿔야 한다는 개념이 부족합니다"처럼 바로 수업 행동으로 이어져야 한다.
- 5학년 분수 MVP는 약분/통분과 분수 덧셈/뺄셈을 중심으로 잡으면 과정 분석의 가치가 잘 드러날 가능성이 높다.
- 풀이 과정을 본다는 말이 꼭 문장 설명을 요구한다는 뜻은 아니다. 학생의 선택, 조작 순서, 멈춤, 수정, 오답 보기 선택만으로도 충분히 많은 사고 데이터를 얻을 수 있다.
- 분수막대는 학생에게는 풀이 도구지만, 시스템에게는 사고 과정을 수집하는 관찰 도구가 될 수 있다.
- 한 번에 한 판단씩 넘기면 학생에게는 쉬운 단계형 풀이가 되고, 교사에게는 개념 단위 진단 로그가 된다.
- 6단계는 고정 규칙이 아니라 기본 템플릿이다. 쉬운 문제는 줄이고, 복합 문제는 늘리되, 9단계 이상이 필요하면 문제를 나누는 편이 좋다.
- 초기에는 학생 부담을 조금 감수하더라도 진단 기준 데이터를 충분히 쌓는 것이 중요하다. 자동 생략은 그 다음 단계의 개인화 기능으로 보는 편이 안전하다.
- 단계별 시간은 "느리다/빠르다"를 평가하기 위한 데이터가 아니라, 학생이 어느 판단에서 오래 고민했는지 찾기 위한 데이터다.
- 질문은 계속 필요하지만, 버튼 모양 같은 미시 결정이 아니라 제품/데이터/AI/교사 리포트/문제 제작처럼 방향이 갈리는 큰 질문을 중심으로 다뤄야 한다.
- 학생에게 분석 결과를 직접 보여주지 않으면 낙인감을 줄일 수 있고, 교사가 맥락을 붙여 지도할 수 있다.
- DeepSeek은 진단을 대신하는 도구가 아니라, 구조화된 로그를 교사용 문장으로 번역하는 도구로 먼저 사용한다.
- 외부 AI API에는 학생 개인정보가 나가면 안 된다. AI가 볼 수 있는 것은 개인을 식별할 수 없는 요약 로그여야 한다.
- 교사용 문장은 똑똑해 보이는 문장이 아니라 빠르게 이해되는 문장이어야 한다.
- UI와 디자인은 나중에 꾸미는 일이 아니라, 학생의 인지 부담과 진단 데이터 품질을 결정하는 핵심 설계 요소다.
- 직접 끌어다 놓기는 데이터가 풍부하지만, 손 조작 능력과 수학 이해가 섞일 수 있다. MVP에서는 자동 생성 방식으로 진단 데이터를 먼저 깨끗하게 만들고, 후속 실험으로 직접 조작 데이터를 검증하는 편이 좋다.
- 교사 첫 화면이 반 전체 오개념 요약이면, 교사는 개인 점수보다 오늘 수업에서 다룰 공통 개념을 먼저 찾을 수 있다.
- 이전 단계로 돌아가는 행동은 단순히 헤맨 흔적이 아니라 자기 수정 능력의 신호가 될 수 있다.
- 작은 진행 막대는 남은 양을 알려주되, `3/6단계` 같은 숫자가 주는 시험 느낌을 줄일 수 있다.
- "모르겠음" 버튼은 포기 버튼이 아니라 막힌 위치를 알려주는 안전한 출구여야 한다.
- "모르겠음" 다음에 바로 힌트를 주지 않으면, 학생이 뒤 단계에서 어떤 개념까지 유지하고 있는지 더 볼 수 있다.
- 이전 버튼을 왼쪽 위에 두면 하단의 주 행동은 `다음`에 집중시킬 수 있다.
- 진행 막대만 보여주는 방식은 단계 정보를 알려주면서도 시험처럼 느껴지는 텍스트 압박을 줄일 수 있다.
- 아이콘만 있는 이전 버튼은 화면을 가볍게 만들지만, 실제 구현에서는 반드시 접근성 라벨이 필요하다.
- 30초 후 나타나는 "모르겠음"은 학생을 압박하는 타이머가 아니라 조용히 열리는 탈출구여야 한다.
- 최상단 중앙 진행 막대는 풀이 화면의 구조를 안정적으로 잡아주면서도 문제와 선택지를 방해하지 않는다.
- 곡선 화살표는 단순 왼쪽 화살표보다 "이전 선택으로 돌아간다"는 느낌을 더 잘 준다.
- "잘 모르겠어요"는 "모르겠음"보다 초등학생에게 덜 딱딱하고 덜 평가적으로 느껴질 수 있다.
- 선택 후 `다음` 버튼을 누르게 하면 실수 클릭을 줄이고, 선택을 바꾸는 과정을 진단 데이터로 남길 수 있다.
- 선택 전 `다음` 버튼을 비활성화하면 "하나를 골라주세요" 같은 오류 안내를 줄일 수 있다.
- 이런 수준의 버튼 모양/위치/색 질문은 매번 사용자에게 묻기보다 기본안을 정해서 빠르게 진행하는 편이 좋다.
- 학생 화면은 정답/오답을 강하게 판정하는 화면이 아니라 사고 과정을 수집하는 화면이므로, 빨간색 오답 피드백은 최소화하는 편이 좋다.

- 문항 순서는 `동치분수 -> 통분 -> 덧셈/뺄셈 -> 문장제` 흐름을 따른다.
- 각 문항은 `steps` 배열로 분절되어 있어, 6단계 고정이 아니라 문제마다 단계 수를 바꿀 수 있다.
- `1/2 + 1/3` 문항은 6단계로 길게 구성해 "한 번에 한 판단" 구조가 잘 드러나게 했다.

### 16.2 학생 화면 구현

- 최상단 중앙에 글자 없는 작은 진행 막대를 배치했다.
- 학생 풀이 화면은 앞으로만 진행한다.
- 이전 단계 버튼은 제거했다.
- 이유: 뒤 단계에서 본 정보가 앞 단계 판단을 오염시켜, 학생이 실제로 이해해서 고른 것인지 뒤에서 본 단서를 이용해 고친 것인지 구분하기 어렵다.
- 학생은 선택지를 고른 뒤 `다음` 버튼을 눌러야 다음 판단으로 넘어간다.
- 선택 전에는 `다음` 버튼이 비활성화된다.
- 학생 화면은 정답/오답 판정을 보여주지 않고, 중립적으로 다음 판단만 진행한다.
- 학생 선택지에는 답 후보 또는 학생이 판단해야 할 이유 후보만 보여준다.
- 학생 선택지 아래에는 오답의 특징, 오개념 이름, 교사용 해석, 왜 틀렸는지 암시하는 설명을 절대 보여주지 않는다.
- 오개념 신호, 교사용 지도 문장, 선택 이유 해석은 데이터에는 남기되 학생 화면 렌더링에서는 제외한다.
- 분수막대는 문제 데이터의 분자/분모 값을 받아 자동 생성된다.
- 30초 후 `잘 모르겠어요` 버튼이 선택지 아래에 나타난다.
- `잘 모르겠어요`도 하나의 선택으로 기록되며, 선택 후 `다음` 버튼을 눌러 진행한다.

### 16.3 수집 데이터

- 단계별 머문 시간
- 첫 선택까지 걸린 시간
- 선택 변경 횟수
- 선택 후 다음 버튼을 누르기까지의 확인 시간
- 선택한 보기와 그 보기가 가진 오개념 신호
- `잘 모르겠어요` 사용 여부

### 16.4 교사 화면 구현

- 교사 첫 화면은 현재 구현에서는 `현재 풀이 진단`으로 시작한다.
- 실제 반 데이터 저장이 붙은 뒤에는 `반 전체 오개념 요약`으로 확장한다.
- 현재 구현에서는 학생이 방금 푼 현재 세션만 분석한다. 현재 세션 기록이 있으면 샘플 데이터를 섞지 않는다.
- 반 전체 요약은 원자료 시간을 그대로 보여주지 않고, `오래 고민함`, `충분히 고민함`, `빠르게 확신함` 같은 해석 문장으로 보여준다.
- 오개념 요약은 학생 수, 판단 수, 해석, 추천 지도 행동을 함께 보여준다.
- 학생별 풀이 흔적에서는 선택, 시간 해석, 행동 신호를 단계별로 확인할 수 있다.
- 이전 단계 이동이 제거되었으므로, 교사 리포트는 머문 시간, 첫 선택 시간, 선택 변경, `잘 모르겠어요` 사용 여부 중심으로 해석한다.
- 샘플 데이터는 넣지 않는다. 현재 세션 기록이 없을 때는 교사 화면에 빈 상태 안내(`아직 현재 풀이 기록이 없습니다`)만 보여준다. 방금 푼 기록과 교사 진단이 항상 일치해야 한다는 원칙 때문이다.

### 16.5 DeepSeek API 연결 상태

- 이번 v0에서는 DeepSeek API를 실제 호출하지 않는다.
- 현재는 규칙 기반으로 오개념 신호를 해석한다.
- 교사 화면에는 DeepSeek에 보낼 수 있는 익명 요약 로그 필드를 명시했다.
- 전송 후보 필드는 문제 ID, 단계 ID, 선택 신호, 시간대 해석, 선택 변경 수, `잘 모르겠어요` 사용 여부, 선택 후 확인 시간이다.
- 학생 이름, 자유 서술 원문, 학교 식별 정보는 보내지 않는 것을 원칙으로 유지한다.

### 16.6 학생용 콘텐츠 누출 하네스

- `scripts/student-content-harness.js`를 추가했다.
- 하네스는 학생 선택지가 `choice.sublabel` 같은 진단 하단 문구를 렌더링하면 실패한다.
- 하네스는 선택지 라벨에 `오개념`, `피드백`, `교사`, `진단`, `흔들`, `확인해야`, `고른 선택` 같은 진단성 문구가 들어가면 실패한다.
- 하네스는 분수막대가 정답 선택지를 직접 보여주거나, 정답 분수와 같은 분자/분모를 시각적으로 먼저 드러내면 실패한다.
- 하네스는 `previous-step`, `previous-button`, `goPrevious`, `backtracksIntoStep`, `navigationEvents`가 학생 앱에 다시 들어오면 실패한다.
- 하네스는 교사 진단 앱 코드가 `MOM_SAMPLE_STUDENTS` 또는 `sampleStudents`를 읽어 현재 세션과 섞으면 실패한다.
- 실행 명령은 `npm test` 또는 `node scripts/student-content-harness.js`다.

### 16.7 다음 구현 후보

- DeepSeek API 실제 연결: 익명 요약 로그만 서버로 보내고, 교사용 문장 초안을 받아오는 구조가 필요하다.
- 교사용 문항 제작 도구: 교사가 단계 수, 선택지, 오개념 신호를 직접 편집할 수 있어야 한다.
- 드래그형 분수막대 실험: 조작 데이터가 수학 이해를 더 잘 드러내는지 별도 모드로 검증한다.
- 실제 반 데이터 저장: 로컬 상태가 아니라 학생 세션별 로그를 저장하는 백엔드가 필요하다.
- 학생별 리포트 압축: 현재는 모든 단계 로그를 길게 보여주므로, 실제 교사용 화면에서는 핵심 신호 중심으로 접는 UI가 필요하다.
