# Middle of Math 완성도 향상 루프

작성일: 2026-08-01
상태: 운영 기준 v1

## 목표

이 루프의 목표는 문항 수를 늘리는 것이 아니라, 이미 만든 진단이 **아이의
수학적 부족 단계를 정확히 드러내고 교사가 다음 수업 행동을 정할 수 있게 하는
것**이다. 한 번에 전체 학년을 다시 검사하지 않는다. 가장 위험한 한 결함군을
선택해 고치고, 변경 범위만 검증한 뒤, 학기 또는 공용 코드 경계에서 전체
게이트를 한 번 실행한다.

## 확정 결정

- 학습자는 한국 초등학교 3~6학년 학생이고, 운영자는 교사다.
- 학생 화면은 실제 문제 풀이에 집중하고, 교사 화면은 관찰 근거와 다음 확인
  단계를 제공한다.
- 한 번의 오답으로 결손을 확정하지 않는다. 서로 다른 판단에서 반복된 근거를
  사용한다.
- 수학적 정확성, 진단 타당성, 학년 어휘, 의미가 맞는 시각자료, 실제 화면
  가독성을 하나의 품질로 본다.
- `DECK6/korean-elementary-learning-map`은 앵커·주제·선수 후보의 편집 근거다.
  특정 학기 배치나 자동 진단을 단독으로 승인하는 자료가 아니다.
- 기존 세트·단원·단계·문항·오개념 ID는 명백한 충돌이 없으면 유지한다.
- Kiro는 사용하지 않는다. Codex가 수정하고, 기존의 같은 Codex 검증
  서브에이전트가 변경 범위만 읽기 전용으로 재검토한다.
- 매 반복마다 전체 Vitest, DB, E2E를 실행하지 않는다. 전체 게이트는 학기
  완료, 발행 후보, 공용 계약 변경 때만 실행한다.

## 하지 않는 일

- 숫자를 채우기 위해 비슷한 문항을 추가하지 않는다.
- 자동 테스트 통과를 교사 내용 승인이나 학생 대상 파일럿 결과로 대신하지
  않는다.
- 낮은 우선순위의 장식 수정을 위해 수학·진단 결함 수정을 늦추지 않는다.
- 검수 상태 세트를 자동으로 발행하지 않는다.
- 학생 원응답이나 개인정보를 외부 AI 검토 입력으로 보내지 않는다.

## 품질 우선순위

| 등급 | 기준 | 처리 |
|---|---|---|
| Blocker | 정답 오류, 필요한 정보가 안 보임, 그림과 수학 불일치, 정답 누출, 데이터 손실·권한 침해 | 즉시 중단하고 수정 |
| High | 오답 산출과 오개념 불일치, 학년 범위 초과, 진단 근거가 다른 능력을 측정, 핵심 접근성 차단 | 다음 작업 전에 수정 |
| Medium | 애매한 문장, 불편한 줄바꿈, 약한 교사 안내, 일부 기기 가독성 저하 | 이번 범위에서 수정하거나 백로그 근거 기록 |
| Low | 의미를 바꾸지 않는 미세한 시각·문구 개선 | 묶어서 후속 처리 가능 |

점수 합산으로 심각한 오류를 가리지 않는다. 종료 판단은 평균 점수가 아니라
등급별 미해결 건수로 한다.

## 한 번의 루프

### 1. 결함군을 하나 고른다

사용자 제보, 정적 감사, 실제 화면, 교사 파일럿 기록에서 가장 높은 등급의
패턴 하나를 고른다. 작업 단위는 `한 단원 전체`가 아니라 다음처럼 원인이
같은 결함 3~8개 또는 공용 렌더러 하나가 기본이다.

- 분수의 슬래시 표기와 부자연스러운 줄바꿈
- 전개도에서 면의 실제 연결 관계 오류
- 오답 선택값과 오개념 산출식 불일치
- 학년보다 어려운 어휘가 정답을 좌우하는 문항

### 2. 증거 묶음을 만든다

각 대상에 대해 다음 다섯 가지를 함께 본다.

1. 원자료의 문항·선택지·정답
2. 각 오답을 실제로 만드는 계산 또는 판단 규칙
3. 관찰하려는 단계·교육과정 앵커·오개념 ID
4. 실제 렌더러가 학생에게 보여 주는 정보
5. 실제 학생 화면 캡처

하나라도 없으면 추측해 승인하지 않는다. 특히 그림 문제는 수치만 맞는지 보지
말고, 그림만 보고도 의도한 관계가 성립하는지 좌표·비례·연결을 확인한다.

### 3. 재발 방지 검사를 먼저 정한다

수정 전에 실패를 다시 잡을 가장 작은 검사를 고른다.

- 콘텐츠 오류: 해당 학기 기본 검사 + 해당 단원 오라클/근거 검사
- 그림 오류: 도메인 기하 검사 + 학생 시각 무결성 검사
- 문장·줄바꿈 오류: 원자료 정적 검사 + 실제 반응형 화면
- 공용 스키마·렌더러 오류: 관련 계약 검사 + 타입 검사 + 빌드
- DB 발행·권한 오류: 해당 pgTAP 파일 + 역할별 권한 검사

새 검사는 실제로 생긴 결함을 잡아야 한다. 같은 사실을 여러 계층에서 반복해
확인하는 검사는 공용 계약 경계를 지킬 때만 추가한다.

### 4. 콘텐츠와 표시를 함께 고친다

문항 데이터만 고치고 잘못된 렌더러를 남기거나, CSS로 가리고 잘못된
수학 데이터를 남기지 않는다. 학생에게 필요한 정보는 실제 화면에 표시하고,
접근성 설명에는 보이는 사실만 담는다. 학생용 문장은 한 문항에서 한 가지
행동만 요청하고 초등 학년 어휘로 쓴다.

### 5. 집중 자동 게이트를 실행한다

콘텐츠 결함군의 기본 명령은 다음과 같다.

```bash
npm run quality:focused -- \
  --set grade6-semester2 \
  --unit "원기둥·원뿔·구" \
  --test packages/content/src/upper-grade-arithmetic-oracle.test.ts \
  --include-visual
```

이 명령은 콘텐츠 정적 감사, 명시한 Vitest 파일, 전체 타입 검사까지만 실행한다.
`--set`은 해당 학기의 기본 테스트 한 파일을 자동으로 더한다. 하지만 학기 기본
검사만으로 관련 계약을 확인했다고 오인하지 않도록 `focused`와 `shared` 모두
명시적 `--test` 파일을 하나 이상 요구한다. 디렉터리나 저장소 밖 경로는 받지
않는다. 공용 렌더러, 스키마, UI 컴포넌트를 바꿨다면 빌드와 번들 누출 검사까지
승격한다.

```bash
npm run quality:shared -- \
  --set grade6-semester2 \
  --test apps/student/src/visual-integrity-harness.test.tsx
```

자동 게이트가 실패하면 뒤 단계를 진행하지 않고 같은 결함군을 고친다.

### 6. 실제 화면을 확인한다

콘텐츠만 바꾼 경우 학생 휴대폰 `390×844`와 대표 태블릿 또는 데스크톱 한
화면을 확인한다. 공용 시각자료·레이아웃·렌더러를 바꾼 경우 다음 세 크기를
모두 확인한다.

- 데스크톱 `1280×720`
- 태블릿 `768×1024`
- 휴대폰 `390×844`

정답을 아는 개발자 시선이 아니라, 처음 보는 학생이 문제의 대상과 요청 행동을
한 번에 알아볼 수 있는지 본다. 한국어 어절이 불필요하게 갈라지는지, 분수·수식·
단위가 한 덩어리로 읽히는지도 확인한다.

### 7. 독립 검토와 보완 재검토를 한다

같은 Codex 검증 서브에이전트에게 원자료, 변경 파일, 선택한 테스트, 실제 화면
근거만 제공한다. 전체 저장소를 다시 감사하게 하지 않는다. 검토자는 다음 형식으로
결과를 남긴다.

```text
VERDICT: APPROVE | REMEDIATE
BLOCKER: n
HIGH: n
MEDIUM: n
LOW: n
RECHECK_SCOPE: 파일·문항·화면
```

결함이 있으면 Codex가 수정하고 같은 검토자에게 지적 범위만 재검토시킨다.
검토자를 바꿔 처음부터 반복하지 않는다.

### 8. 닫고 다음 결함군으로 간다

다음 조건을 모두 만족하면 한 번의 루프를 닫는다.

- Blocker 0, High 0
- 변경 범위의 Medium 0, 또는 사유·담당·재검토일이 있는 백로그
- 집중 자동 게이트 통과
- 필요한 실제 화면 크기 확인
- 독립 보완 재검토 `APPROVE`
- 새 회귀 검사가 최초 결함을 실제로 잡는다는 증거

Low는 묶어서 처리할 수 있다. 같은 원인이 세 번 나오면 개별 문항 수정으로
끝내지 않고 스킬·하네스·공용 작성 도구의 규칙으로 승격한다.

## 검증 범위 승격표

| 변경 | 자동 검증 | 화면 | 독립 검토 |
|---|---|---|---|
| 문항 문구·선택지·근거 | 정적 감사 + 학기 기본 + 단원 오라클 + 타입 | 휴대폰 + 대표 1개 | 변경 문항만 |
| 한 시각자료 데이터 | 위 검사 + 관련 기하/시각 검사 | 세 크기 | 해당 자료·렌더 결과 |
| 공용 렌더러·스키마·UI | `quality:shared` + 관련 계약 검사 | 세 크기 + 영향 학기 표본 | 공용 계약과 대표 문항 |
| 교차표·런타임 생성기 | shared + 교차표/스냅숏 재현 | 영향 화면 표본 | digest·범위·누출 |
| migration·RLS·발행 RPC | 관련 pgTAP + 역할별 권한, 학기 끝에 전체 DB | 영향 운영 화면 | SQL 변경 범위 |
| 학기 완료·발행 후보 | `quality:release` | 학생·교사 대표 여정 | 최종 미해결 목록 |

## 학기·릴리스 전체 게이트

다음 상황에서만 전체 게이트를 실행한다.

- 한 학기의 모든 단원 루프가 닫힘
- 발행 후보를 만들기 직전
- 공용 진단 스키마·발행 경계·보안 모델이 바뀜
- 좁은 검사로 영향 범위를 신뢰할 수 없음

```bash
npm run quality:release
```

이 명령은 콘텐츠 정적 감사, 교차표·상위 학년 런타임 재현, 꺾은선그래프 좌표
퍼즈, 전체 타입·단위·레거시 검사, 빌드·번들 누출, DB·pgTAP, 브라우저 여정,
smoke 계약을 한 번 실행한다. 로컬 Supabase와 Playwright 브라우저가 준비되어
있어야 한다.

## 운영 백로그 형식

다음 표를 작업 문서에 복사해 사용한다.

| ID | 등급 | 세트/단원 | 결함군 | 학생·교사 영향 | 재현 근거 | 담당 | 상태 | 재검토일 |
|---|---|---|---|---|---|---|---|---|
| Q-001 | High | 예: 6-2 5단원 | 예: 전개도 연결 오류 | 다른 면 관계를 측정 | 문항 ID·화면 | Codex | open | 2026-08-02 |

동시에 여는 결함군은 하나로 제한한다. 결함 수보다 `같은 원인의 재발 횟수`,
`학생 판단 오염 가능성`, `교사 행동을 바꾸는 정도`를 우선순위로 삼는다.

## 파일럿으로 확인할 것

자동·독립 검토를 통과해도 다음은 실제 수업에서만 알 수 있다.

- 학생이 문항 요청을 다시 물어보는 빈도
- 수학은 알지만 어휘·조작 때문에 틀린 사례
- 교사가 리포트만 보고 다음 확인 질문을 고를 수 있는지
- 반복 오개념이 실제 학생 풀이 설명과 맞는지
- 한 학생 진단과 교사 확인에 걸린 시간

이 관찰은 새 문항을 무조건 추가하는 근거가 아니라, 다음 결함군을 선택하는
입력으로 사용한다.
