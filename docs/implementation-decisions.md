# Middle of Math — Phase 1 구현 결정

작성일: 2026-07-22
상태: 사용자 승인 후 구현 기준

## 범위 변경

- 첫 운영 진단은 `5학년 분수` 대신 `3학년 2학기 수학`으로 한다.
- 운영 화면에서는 곱셈, 나눗셈, 원, 분수, 들이와 무게, 그림그래프의 6개 단원을 다룬다.
- 기존 5학년 분수와 수 세기 데이터는 새 콘텐츠 패키지로 옮길 때 참고하는 legacy fixture로만 보존한다.
- 개인 리포트는 `교사용 리포트`와 `학부모 전달용 리포트`로 분리한다.
- Phase 1의 학부모 리포트는 교사가 확인한 뒤 인쇄하거나 PDF로 저장하는 전달용 화면까지 포함한다. 보호자 계정·이메일 자동 발송은 포함하지 않는다.

## 3학년 2학기 콘텐츠 기준

2022 개정 교육과정은 3~4학년군 성취기준을 제시하므로, `3학년 2학기` 순서는 Middle of Math의 진단 세트 manifest에서 관리한다. 교육과정 원문을 학생 문항에 복사하지 않고 안정적인 성취기준 ID만 앵커로 둔다.

|---|---|---|
| 곱셈 | `[4수01-04]` | 자릿값에 따라 부분곱을 구성하는가 |
| 나눗셈 | `[4수01-05]`, `[4수01-06]` | 등분·포함 의미, 몫과 나머지 |

| 들이와 무게 | `[4수03-17]`, `[4수03-19]`, `[4수03-20]` | 단위 관계, 측정값 해석, 합과 차 |

## 학생 식별과 입장 정책

### 비교한 패턴

- Google Classroom은 6~8자리 영숫자 클래스 코드를 사용하고, 교사가 코드를 재설정하거나 비활성화할 수 있다. 계정이 있어 기기 간 등록 상태를 유지한다.
- Kahoot은 계정 없이 PIN과 닉네임으로 참여할 수 있지만, 나갔다 다시 들어오면 새 닉네임으로 재참여한다.
- Seesaw는 어린 학생에게 QR 또는 텍스트 코드를 제공하고, 클래스 코드를 학교·교사가 보호해야 하는 접근 수단으로 취급한다.
- Supabase anonymous user는 일반 `anon key`와 다르며 authenticated 역할로 RLS를 적용할 수 있지만, 브라우저 데이터를 지우거나 다른 기기를 쓰면 같은 anonymous identity를 복구할 수 없다.

참고:

- [Google Classroom 클래스 코드 입장](https://support.google.com/edu/classroom/answer/15605102?hl=en)
- [Kahoot PIN·닉네임 입장](https://support.kahoot.com/hc/en-us/articles/360039890713-Kahoot-join-How-to-join-a-Kahoot-game)
- [Seesaw 학생 로그인 방식](https://seesaw.com/get-started/)
- [Supabase anonymous sign-in과 RLS](https://supabase.com/docs/guides/auth/auth-anonymous)

### Middle of Math 결정

- `학생 번호`를 클래스 안의 필수 안정 식별자 `roster_key`로 사용한다.
- `별칭`은 선택 표시명이다. 교사·학부모 화면에서 번호와 함께 또는 번호 대신 보여줄 수 있다.
- 실명 입력 필드는 만들지 않는다.
- 클래스 코드는 혼동하기 쉬운 문자를 뺀 6자리 대문자·숫자로 자동 생성한다.
- 교사는 코드를 재발급하거나 즉시 비활성화할 수 있다.
- 같은 브라우저에서는 anonymous auth와 IndexedDB를 이용해 자동으로 이어간다.
- 새 기기에서는 기존 세션을 덮어쓰지 않고 새 시도로 저장한다. 교사는 충돌 상태를 확인하고 사용할 세션을 결정한다.
- 완료되지 않은 세션은 반 오개념 집계에서 제외하고 `진행 중` 인원으로만 표시한다.

## 교사용과 학부모용 리포트 분리

Google Classroom은 교사 화면의 상세 학생 작업과 보호자 요약을 분리하고, 보호자는 교사·학생 화면 전체에 접근하지 않는다. Middle of Math도 같은 경계를 사용한다.

- 교사용: 오개념 후보, 교육과정 앵커, 판단 단위 이벤트, 시간·변경·불확실성 신호, 엔진 버전
- 학부모용: 관찰한 강점, 현재 연습할 한두 가지, 가정에서 사용할 짧은 질문, 확정 진단이 아니라는 안내
- 학부모용에서 제외: 다른 학생과의 비교, 반 순위, 원본 이벤트, 오개념 코드, 엔진·콘텐츠 내부 ID

참고: [Google Classroom 보호자 이메일 요약의 접근 범위](https://support.google.com/edu/classroom/answer/7126518?hl=en)

## 해석 규칙 v3

학생의 한 번의 선택만으로 부족한 학습 단계를 확정하지 않는다. `rules-3.0.0`은 학생 이벤트를 바꾸지 않고 같은 입력을 다시 재생해 `추가 관찰`과 `반복 확인`을 구분한다.

| 조건 | 교사 화면 | 보호자 공유본 |
|---|---|---|
| 같은 신호가 한 문항에서만 관찰됨 | `한 번 관찰` | 연습 항목에 넣지 않음 |
| 같은 신호를 확인할 문항이 한 개뿐임 | `한 번 관찰` | 연습 항목에 넣지 않음 |
| 서로 다른 두 문항에서 같은 신호가 관찰됨 | `반복 확인` | 최대 2개까지 연습 항목에 포함 |
| `잘 모르겠어요` 또는 정의되지 않은 선택 | `한 번 관찰` | 연습 항목에 넣지 않음 |
| 응답 위치 편향 또는 모든 근거가 지나치게 빠름 | `한 번 관찰` | 연습 항목에 넣지 않음 |
| 이전 `rules-2.0.0` 저장 결과 | `한 번 관찰` | 새 엔진 재해석 전 확정하지 않음 |

반복 확인에는 서로 다른 판단 ID가 2개 이상 필요하고, 해당 신호를 관찰할 기회도 2개 이상이어야 한다. 정답 반응은 반대 근거로 함께 보여 주되 이미 두 문항에서 반복된 관찰을 지우지는 않는다. 위치 편향은 적어도 5개 응답, 제시 순서 근거 80% 이상, 한 위치 선택 80% 이상일 때만 근거 품질 경고로 사용한다. 선택까지 1.5초 미만이면서 전체 응답도 3초 미만인 기록만 지나치게 빠른 응답으로 본다.

이 임계값은 교사가 조절하는 평가 기준이 아니라 얇은 근거를 확정하지 않기 위한 보수적 엔지니어링 기준이다. 임계값을 바꾸면 규칙 엔진 버전도 함께 올리고, 이전 해석 실행은 수정하거나 삭제하지 않는다.

## UI 방향

- DESIGN.md의 색·타이포·간격 토큰을 그대로 코드 토큰으로 만든다.
- 학생 화면의 기억 장치는 `판단선`: 텍스트 단계 번호 없이 한 칸씩 전진하는 가는 진행선이다.
- 교사 화면의 기억 장치는 `근거선`: 교육과정 앵커에서 작은 학습 단계와 실제 선택까지 이어지는 세로 연결선이다.
- 학생 화면은 차분하고 넓게, 교사 화면은 표보다 우선순위와 근거 연결이 먼저 보이게 한다.
- 학부모 리포트는 A4 인쇄 시 한 장에 들어가는 단일 열 문서로 만든다.
# 교육과정 교차표는 런타임 진단과 분리한다

2026-07-29부터 3학년 2학기 콘텐츠의 17개 성취기준과 32개 진단 단계를 고정된 `DECK6/korean-elementary-learning-map` 커밋에 대조한다. 외부 자료는 성취기준·주제·선수 관계를 찾는 편집 근거이며, 학생 응답을 해석하는 진단 규칙에는 들어가지 않는다.

외부의 성취기준 수준 주제와 Middle of Math의 더 작은 진단 단계가 같다고 주장하지 않기 위해 현재 32개 단계는 모두 `topic-partial`이다. 외부 선수 관계 6개도 후보로만 남기며 로컬 선수 단계로 자동 승격하지 않는다. 고정 snapshot과 교차표의 SHA-256이 달라지거나 행·범위·라벨이 어긋나면 2.x 발행을 차단한다.

# U6 오답 근거와 심각도 구현 결정

작성일: 2026-07-30
상태: `2.1.0` 자동 검증 통과, 교사 내용 검수 대기

## D1. 런타임 신호는 단계마다 하나를 유지한다

오답 128개를 설명하기 위해 런타임 신호를 64개로 늘리지 않는다. 학생 응답
해석은 기존 단계 신호를 유지하고, 더 세밀한 오개념 ID·제목·근거·도출 과정은
편집 블루프린트에만 둔다. 이렇게 해야 기존 이벤트와 리포트 호환성을 지키면서
오답끼리 다른 사고 과정을 검수할 수 있다.

## D2. 오답 근거는 선택지에서 역산한다

먼저 실제 오답 값이 나오는 계산 또는 잘못 적용한 판단 규칙을 한 줄로 재현한다.
그 뒤 교사가 확인할 수학적 판단을 별도 문장으로 적는다. 선택지 자체를
되풀이하거나 신호 문구와 다른 오답 설명을 복사하면 발행 게이트가 차단한다.
각 오개념 ID는 학습 단계 ID로 시작하며 32개 단계마다 2개씩, 모두 64개다.

## D3. 심각도는 검토 우선순위이며 자동 진단이 아니다

핵심 개념 관계는 `high`, 주요 계산·표현 절차는 `medium`, 보조 전략은 `low`로
검토했다. 기존 14개 신호는 바꾸지 않고 추가 20개에만 기준을 적용했다.
전체 34개 분포는 `high 10 / medium 18 / low 6`이고, fallback 2개를 뺀
진단 신호 32개는 `high 10 / medium 18 / low 4`다. 한 번 관찰된 신호는
심각도와 무관하게 확정하지 않으며 `rules-3.0.0`의 반복 근거 기준을 그대로 쓴다.

## D4. 편집 근거는 학생과 학부모에게 보내지 않는다

오개념 제목, 오답 근거, 도출 과정, 공통 신호 설명은 `DiagnosisSet`과 분리한다.
학생 앱은 답 후보만 받고, 학부모 공유본은 반복 확인된 지원 영역만 받는다.
스튜디오는 이 원장을 읽기 전용으로 표시한다. 초안의 선택지 ID가 원장과
어긋나면 근거를 추측해 연결하지 않고 명시적인 불일치 경고를 보여 준다.

진단 무결성 게이트 `gate-1.0.0`, 블루프린트 `2026-07-30.2`, 콘텐츠
`2.1.0`의 checksum을 함께 고정한다. 자동 오류는 0개이며, 외부 학습맵의
후보·자문 상태를 알리는 출처 경고 2개는 의도적으로 유지한다.

# U8 초3-1 선수학습 연결 구현 결정

작성일: 2026-07-30
상태: 자동 검증 통과·교사 내용 검수 대기

## D1. 초3-1은 초3-2 안에 섞지 않고 별도 진단 세트로 둔다

`grade3-semester1` `1.0.0`을 `review` 상태로 만든다. 4개 단원, 8개 단계,
16개 판단을 두며 각 단계는 직접 확인과 적용·전이 판단을 하나씩 가진다.
초3-2 `2.1.0`의 문항, checksum, 블루프린트, 교차표는 바꾸지 않는다.

## D2. 고정 원본과 다른 성취기준 추정을 거부한다

초기 계획의 `[4수03-05]` 평면도형 제안은 고정된 DECK6 원본과 맞지 않아
철회했다. 길이는 `[4수03-16]`으로 연결한다. 외부 자료는 3~4학년군까지만
확인하므로 모든 1학기 배치는 로컬 편집 결정이라고 교차표에 명시한다.

## D3. 학기 사이는 별도 자문 그래프로 연결한다

세트 내부 `prerequisiteStageIds`는 같은 학기의 순서를 유지한다. 초3-1에서
초3-2로 향하는 6개 연결은 digest가 있는 별도 그래프에 두고 모두
`advisory: true`로 고정한다. 교사 화면에는 편집 참고로만 보여 주며 진단
엔진, 학생 화면, 학부모 공유본에는 자동 판정으로 전달하지 않는다.

## D4. 나머지 1학기 범위는 근거 검수 뒤 U8b에서 확장한다

평면도형, 시간, 덧셈과 뺄셈, 소수는 문항 수를 채우기 위해 추정해 넣지
않는다. 공식 학기 배치와 한 문항당 관찰 행동을 확인한 뒤 별도 버전으로
추가한다. 현재 세트는 자동 게이트 통과가 발행 승인을 뜻하지 않으며 다른
교사의 내용 검수를 받아야 한다.

## D5. 학년군 성취기준과 로컬 학기 배치를 DB에서 분리한다

교육과정이 3~4학년군으로 제시한 `[4수01-04]`, `[4수01-05]`,
`[4수01-06]`, `[4수01-09]`는 `shared_across_semesters=true`로 표시한다.
발행 가드는 같은 학년이면서 공통 앵커이거나 정확히 같은 학기인 앵커만
허용한다. 이 구조로 초3-1이 공통 수와 연산 기준을 정식으로 참조하면서도
`[4수03-16]`과 `[4수03-17]` 같은 학기 전용 편집 배치가 섞이지 않게 한다.
콘텐츠 스튜디오의 학기 필터도 해당 학기 전용 앵커와 공통 앵커를 함께
조회한다.

# U9 초4 확장 기반 구현 결정

작성일: 2026-07-30
상태: U9.0-a 인프라 구현·독립 검증 대기

## D1. 학년군 출처와 특정 학년 사용 승인을 분리한다

`grade_band="3-4"`는 교육과정이 성취기준을 제시한 범위를 기록할 뿐,
그 성취기준을 초3 또는 초4 어느 학기에 배치해도 된다는 승인이 아니다.
DB는 다음 세 축을 따로 관리한다.

- `grade_band`: 원문의 학년군 출처
- `shared_across_semesters`: 같은 학년의 다른 학기 사용 승인
- `shared_across_grade_band`: 같은 학년군의 다른 학년 사용 승인

발행 정합성 가드는 학년과 학기를 각각 검사한다. 원래 학년이 아니면
`shared_across_grade_band=true`이고 manifest 학년이 `grade_band` 안에
있어야 한다. 원래 학기가 아니면 별도로
`shared_across_semesters=true`여야 한다. 학년군 값만 보고 자동 승인하지
않는다.

현재 등록된 `[4수]` 앵커 18개에는 `grade_band="3-4"`만 기록하고
`shared_across_grade_band`는 모두 false로 둔다. 초4 코드→단원→학기 표를
교과 검수자가 승인하기 전에는 기존 초3 앵커를 초4에서 사용할 수 없다.
pgTAP은 트랜잭션 안에서만 한 앵커의 학년군 공유 플래그를 켜 양성 경로를
검증하고 마지막에 되돌린다.

TypeScript 레지스트리도 같은 원칙으로 `gradeBand`,
`sharedAcrossSemesters`, `sharedAcrossGradeBand`를 구분한다.
`findAnchorForSet()`은 정확한 학년·학기를 우선하고, 학년군 공유가
명시되지 않았거나 서로 다른 라벨 후보가 겹치면 추측하지 않고
`undefined`를 반환한다. 현재 조회에는 검수된 최신 라벨을 사용하고,
이미 고정된 3-2 v1 checksum 재현에만 `v1Label`을 사용한다.

## D2. 선수 그래프는 소유자와 중복 범위를 명시한다

학년별 그래프가 늘어날 때 다음 오류를 발행 전에 차단한다.

- `SPG_EDGE_OUTSIDE_OWNER`: 출발과 도착 어느 쪽에도 그래프 소유 세트가 없음
- `SPG_EDGE_DUPLICATED_ACROSS_GRAPHS`: 같은 출발·도착 연결을 여러 소유
  그래프에 중복 등록
- `SPG_GRADE_SKIP_UNJUSTIFIED`: 중간 학기를 하나라도 건너뛰어 연결하면서 구체적인
  건너뛰기 근거가 없음

중간 학기를 하나라도 건너뛰는 연결은 검수 근거에 `학기 건너뛰기:` 표식과 10자 이상의
이유를 남긴다. 이 규칙은 장거리 연결을 금지하기보다, 중간 학기의
관련 단계가 왜 연결에 포함되지 않았는지 사람이 다시 확인할 수 있게 한다.

U9.0-a에서는 초4 문항·앵커·스냅숏을 추가하지 않는다. 기존 초3-1,
초3-2 세트와 고정 그래프·교차표·스냅숏은 그대로 유지한다.

## D3. 초4 학기 배치는 별도 검토 원장으로 승인받는다

U9.0-b에서 고정 DECK6 커밋의 3~4학년군 전체 47개 성취기준을
`kr-learning-map.grade34.snapshot.json`으로 보존했다. 스냅숏은
47개 기준, 142개 주제, 6개 선수 후보만 담으며 학생 진단을 지원하지
않는다고 명시한다. 코드마다 업스트림의 `module`, `focus`, 공식 자료
locator를 함께 보존한다. 원본 3파일의 해시와 스냅숏 digest를 테스트로
고정한다. locator의 기준 문서인 NCIC `[별책8] 수학과 교육과정.pdf`도
URL·바이트 수·쪽 수·SHA-256을 `sources`에 보존해 같은 원문에서 위치를
다시 확인할 수 있게 한다. 다만 DECK6가 기록한 `pdftotext` 줄 번호는
추출 도구가 고정되지 않아 로컬에서 재현되지 않으므로
`locatorProvenance="upstream-recorded"`,
`locatorLocallyReproducible=false`로 명시하고 승인 근거에서 제외한다.
대신 사람이 검토할 수 있는 상류 `evidence.basis` 문장을 함께 보존한다.

4학년 코드→단원→학기 배치는 경기도교육청의 2025학년도 3~4학년
1·2학기 수업-평가 계획 예시와 대조해
`grade4-curriculum-placement.json`에 기록한다. 전역 상태는
`pending-teacher-review`이며 4-1·4-2 각각 6개 단원이다. 2026-07-30
A1에서 `teacher:workspace-owner`가 4-1 큰 수와 각도 두 단원만
부분 승인했고, 나머지 10개 단원은 승인 대기 상태를 유지한다.
`[4수04-03]`은 두 학기에 모두 나타나지만, 승인 전에는 학기 공유로
등록하지 않는다. 기존 초3에도 쓰인 네 코드의 학년군 공유 여부도 교사가
코드별로 승인한다. 단원별 전체 코드 목록과 두 공유 후보 집합은 테스트로
고정하고, 공식 게시물 첨부 PDF의 주소·바이트 수·SHA-256은 검토 원장에
기록하되 파일 자체는 복제하지 않는다. 2학기 PDF 부록에는 학년군 전체
47개 코드가 있으므로 코드의 단순 존재를 학기 배치 근거로 쓰지 않고,
단원 문맥과 교사 승인을 별도로 요구한다.

전체 원장의 전역 상태와 별도로 각 단원에 `reviewStatus`, `reviewedBy`,
`reviewedAt`을 둔다. `inspectGrade4PlacementApproval()`은 초4 진단
세트가 승인된 단원만 선언하고 그 단원의 성취기준을 빠짐없이 포함하는지
검사한다. 이 검사는 아직 coverage blueprint가 없는 초안에도 적용해,
큰 수·각도 A1 승인만으로 뒤 단원이나 공유 후보가 함께 열리지 않게 한다.
검사는 setKey와 manifest의 ID·학년·학기도 대조한다. 승인자 ID는
`teacher:<식별자>`, 승인 시각은 시간대가 있는 ISO-8601이면서 현재
시각보다 늦지 않아야 한다. 전역 `approved`와 12개 단원의 전체 승인은
항상 함께 바뀌어야 한다. Studio에는 동결된 읽기 전용 승인 요약만
노출하고 학생 런타임 export에는 포함하지 않는다.

# A2-5 초4-1 곱셈과 나눗셈 구현 결정

## D2. 계산 단원도 작은 판단 단계로 분리한다

부족을 확정하지 않고 반복 근거를 수집한다.

## D3. 불필요한 그림을 만들지 않는다

12문항은 수식과 짧은 문장만으로 수학적 판단이 완결된다. 장식용
세로셈 그림이나 정답을 암시하는 도식을 추가하지 않고 `visual:none`을
사용한다. 대신 세 화면 크기에서 어절 내부 줄바꿈과 가로 넘침을
실브라우저로 검사한다.

## D4. 1.3.0은 불변으로 두고 1.4.0을 추가한다

`grade4-semester1@1.3.0`의 54문항·108개 오답 해석은 수정하지 않는다.
`1.4.0`은 여기에 12문항·24개 해석을 append-only로 더한
6단원·33단계·66문항 발행본이다. 신규 설치와 이전 seed 업그레이드를
각각 격리 DB에서 재생하고 두 버전의 checksum·해설 수를 함께 고정한다.
DB 테스트는 `1.4.0`의 체크섬 상수와 manifest 내부 체크섬이 모두
일치해야 통과하도록 해 생성기나 seed의 우발적 변화를 막는다.
