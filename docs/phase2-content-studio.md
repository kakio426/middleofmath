# Phase 2 — 콘텐츠 제작 스튜디오

작성일: 2026-07-22
상태: 구현 기준

## 운영 범위

- `apps/studio`는 내부 콘텐츠 제작자·검수자·관리자만 사용한다.
- 데이터 모델은 초등 1–6학년, 1·2학기를 지원한다.
- 첫 제작·검수 파일럿은 `grade3-semester2`이며 기존 `1.0.0`을 불변 기준 버전으로 가져온다.
- 일반 교사는 발행된 버전을 배정할 수 있지만 초안과 검수 기록에는 접근하지 않는다.
- 운영 런타임의 콘텐츠 원장은 Supabase의 불변 발행본이다. `packages/content`는 시드·내보내기·백업·테스트 fixture로 유지한다.

## 역할과 상태 전이

| 역할 | 허용 작업 |
|---|---|
| 제작자 | 자기 초안 생성·편집·자동 저장·검수 요청 |
| 검수자 | 제출된 리비전 열람·필드 의견·변경 요청·승인 |
| 관리자 | 역할 관리·초안 재배정·교육과정 카탈로그 관리·발행·종료 |

```text
draft → in_review → changes_requested → draft
                 └→ approved → published
published → retired
```

- 작성자와 승인자는 다른 계정이어야 한다.
- 검수 요청은 정확한 리비전을 고정한다. 이후 내용이 바뀌면 승인이 무효화된다.
- 발행은 트랜잭션 RPC만 허용한다. DB의 insert trigger가 클라이언트 검증 결과를 신뢰하지 않고 참조·순환·안정 ID·학생 문구·상호작용 규칙을 다시 확인한다.
- 발행된 콘텐츠는 UPDATE·DELETE하지 않는다. 새 배정을 막아야 할 때만 `retired`로 전환한다.

## 편집과 검증

- 입력 정지 1초 후 자동 저장하고 `revision` 낙관적 잠금으로 오래 열린 화면의 덮어쓰기를 막는다.
- 충돌은 조용히 합치지 않는다. 서버 버전과 로컬 사본을 보존하고, 복구를 선택하면 기존 서버 초안을 덮지 않는 별도 초안으로 만든다. 복구 키는 제작자와 초안 ID별로 격리한다. 복구 초안은 알 수 없는 키·잘못된 타입·안정 ID 제거를 거부하되, 작성 중인 빈 문구는 허용하고 완성도 검사는 검수 요청과 발행 시점에 수행한다.
- 구조 편집은 단원 → 작은 학습 단계 → 판단 단위의 안정 ID를 보존한다.
- 학생 미리보기는 `packages/ui`의 실제 렌더러를 사용하며 세션·관찰 이벤트를 만들지 않는다.
- 편집 가능한 상호작용은 현재 검증된 `choice`, `fraction-bar`, `measurement`, `pictograph`로 제한한다.
- Zod 구조, ID·참조 무결성, 선수 단계 순환, 단일 정답, 오답 신호, 교육과정 앵커, 렌더러 호환성, 학생 문구 누출을 모두 통과해야 검수를 요청할 수 있다.

## 리포트 문구 경계

콘텐츠 신호는 같은 관찰에서 파생되더라도 수신자별 원문을 분리한다.

- 교사용: `teacherInterpretation`, `teachingMove`
- 학부모용: `parentSummary`, `homePrompt`

학부모 문구에는 오개념 코드, 정오답 수, 순위, 다른 학생 비교, 내부 엔진·콘텐츠 ID를 넣지 않는다. Phase 2는 문구 제작과 미리보기까지만 담당하며 자동 발송은 포함하지 않는다.

## 버전과 런타임

- 신규 세트는 `1.0.0`, 기존 세트 수정은 patch 증가가 기본이다.
- 관리자는 호환성이 바뀌는 발행에서 minor·major를 선택하고 릴리스 노트를 남긴다.
- assignment는 `diagnosis_set_id`로 정확한 발행 버전을 고정한다.
- 학생 앱은 배정 버전 전체 JSON을 Zod와 checksum으로 검증하고 IndexedDB에 캐시한다. checksum은 키를 정렬한 공백 없는 canonical JSON에서 `manifest.checksum`을 빈 문자열로 둔 뒤 계산한 SHA-256이다. 콘텐츠 객체는 strict 스키마로 알 수 없는 필드를 거부하고, 파싱 과정에서 문자열을 변환하지 않아 DB와 학생 런타임이 같은 바이트 의미를 유지한다. 모든 ID는 앱과 DB에서 공백 없는 비어 있지 않은 문자열로 동일하게 검증한다.
- 오프라인에서는 이미 받은 정확한 버전만 사용하며 패키지 기본값이나 다른 버전으로 자동 대체하지 않는다.
- 기존 과제와 세션은 `1.0.0`에 남고 신규 발행본은 새 배정에서만 선택한다.

## 완료 게이트

1. 제작자가 `1.0.0`을 복제해 변경하고 자동 저장할 수 있다.
2. 제작자의 자기 승인은 RLS/RPC 모두에서 거부된다.
3. 다른 검수자가 승인한 리비전만 `1.0.1`로 발행된다.
4. 발행 콘텐츠와 패키지 export의 checksum을 재현할 수 있다.
5. 일반 교사는 발행본만, 학생은 자기 과제의 정확한 버전만 읽는다.
6. 태블릿 라이트·다크 미리보기와 기존 학생 하네스가 모두 통과한다.

## 현재 파일럿 구현 경계

- `grade3-semester2` 기준본 복제 → 자동 저장 → 2인 검수 → patch 발행 → 교사 클래스 배정 → 학생의 exact version 조회까지를 첫 수직 경로로 구현한다.
- 새 세트, 단원·학습 단계 추가/삭제, 관리자 역할·교육과정 카탈로그 UI는 다음 스튜디오 확장 묶음이다. 도메인 타입·검증·저장 포트는 1–6학년 공통 구조로 먼저 일반화했다.
- DB 테스트는 임의 학생의 전체 발행본 조회, 타 작성자 초안 조회, 안정 ID 제거, 학생 진단 문구 삽입, 알 수 없는 콘텐츠 필드, client checksum 위조를 부정 시나리오로 검증한다.
