## A4-1 — 자연수의 혼합 계산

상태: **구현·전체 회귀·Kiro Opus 5 독립 검증 통과**

목표: `[6수01-01]`을 계산 결과만 맞히는 문제가 아니라 어떤 계산
순서에서 무너지는지 찾는 5단계, 10문항으로 구현한다.

단계 후보:

1. 곱셈이 덧셈·뺄셈보다 먼저임을 판단
2. 나눗셈이 덧셈·뺄셈보다 먼저임을 판단
3. 같은 순위의 계산을 왼쪽부터 수행
4. 괄호 안을 먼저 계산
5. 괄호 처리 뒤 전체 계산 순서를 다시 적용

범위 제한:

- 자연수와 나누어떨어지는 나눗셈만 사용
- 음수, 소수, 분수, 나머지, 중괄호·대괄호는 사용하지 않음
- 한 식에 계산 기호는 최대 3개
- 문장 이해가 아니라 식과 계산 순서를 직접 묻는 짧은 표현 사용
- 보기 2개는 각각 특정 오개념 계산 결과여야 하며 임의 숫자를 넣지 않음

구현 결과:

- 한 단원·5단계·10문항, 단계마다 direct·transfer 2문항
- 각 문항의 두 오답은 실제 산술로 재현되는 계산 순서 오류로 고정하고,
  여러 단계에 공통인 `첫 중간값에서 멈춤`은 별도 공통 신호로 묶음
- 학생 문구는 짧은 식과 `계산 순서대로 풀어 보세요.`만 사용
- 띄어 쓴 수식 전체를 하나의 줄바꿈 단위로 묶어 연산자와 피연산자가
  서로 다른 줄로 갈라지지 않게 함
- 10문항 안에서 정답 위치가 학생별로 3·3·4회 순환하고, 선택지 안의
  두 오답 순서는 세션 해시로 재현 가능하게 섞음
- 1280×720, 768×1024, 390×844, 360×800의 밝은/어두운 화면에서
  10문항을 모두 완주하는 실브라우저 회귀 추가
- 콘텐츠는 `review`, DB 성취기준·허용 목록·진단·교사용 오답 원장에는
  아직 발행하지 않으며 pgTAP이 이 경계를 고정

## A4-2 — 약수와 배수

상태: **5단계·10문항 구현·전체 회귀·Kiro Opus 5 독립 검증 통과**

- `factors.list-divisors`: 1과 자기 자신을 포함하고 나머지 없이
  나누어지는 수를 빠짐없이 찾는다.
- `factors.common-and-greatest`: 두 약수 목록의 공통값과 가장 큰 값을
  찾는다.
- `multiples.list-multiples`: 1배부터 차례로 곱해 자기 자신부터 배수를
  쓴다.
- `multiples.common-and-least`: 두 배수 목록의 공통값과 가장 작은 값을
  찾는다.
- `factors-multiples.apply-in-context`: 똑같이 나누어 담는 상황과 다시
  함께 일어나는 상황을 구별한다.

각 단계는 direct·transfer 두 문항을 가지며, 두 오답은 두 문항에서 같은
오해가 반복되도록 독립 산출 함수로 역산한다. 공약수 목록과 최대공약수,
공배수 목록과 최소공배수는 한 보기에 합치지 않고 각각 한 행동만 묻는다.
10문항 모두 `visual:none`이고
긴 수 목록은 개별 수와 쉼표를 같은 읽기 토큰으로 묶되 쉼표 뒤에서만
줄바꿈한다. 두 단원은 각각 10문제·약 5분의 독립 카드와 세션으로 제공한다.

최종 콘텐츠 체크섬은
`64b412abecafd0d5e7641441d124667cc3e4f54c1b2b92f600983fb62cc3093c`다.
Kiro Opus 5는 복합 보기와 `/` 구분자, 목록 산출 검산, 피연산자 복사
충돌을 차례로 지적했고 보완본 재검증에서 `VERDICT: APPROVE`,
blocker·high·medium 0건, `NEXT_UNIT_READINESS: READY`를 반환했다.

범위는 자연수와 두 수의 공약수·공배수까지이며, 소인수분해·호제법·세 수
문제·분수 적용은 제외한다. 콘텐츠는 계속 `review` 상태이고 DB 발행
원장에는 넣지 않는다.

## A4-3 — 대응 관계

상태: **5단계·10문항 구현·전체 회귀·Kiro Opus 5 독립 검증 통과**

- `correspondence.pair-from-table`: 완전한 3행 대응표에서 두 양을 함께
  보고 표 밖의 새 짝을 찾는다.
- `correspondence.symbol-expression`: 표의 모든 행에 맞는 □·△ 한 연산
  식을 고른다.
- `correspondence.base-and-dependent`: □로 △를 구하는 계산 방향을
  구별한다.
- `correspondence.apply-backward`: 문제에 주어진 기호식의 계산을 반대로
  하여 처음 양을 찾는다.
- `correspondence.change-together`: 문제에 주어진 관계식으로 두 양의
  변화량을 함께 계산한다.

각 단계는 direct·transfer 두 문항과 반복되는 두 오개념을 가진다.
Kiro의 첫 독립 검증은 생활 맥락 전이 문항이 관계 찾기와 적용을 동시에
요구하고, 추상 기호 헤더와 구체 헤더를 한 쌍 안에서 바꾸어 실패 원인을
흐린다고 지적했다. 이에 역방향·변화량 문항 모두 관계식을 직접 제시하고,
표 헤더는 구체적인 두 양으로 통일했다. 단계별 두 문항의 정답 크기 순위도
서로 다르게 고정했으며 정답과 같은 자릿수의 오답을 하나 이상 둔다.

콘텐츠는 세 단원·15단계·30문항, 단원별 10문제·약 5분 카드다. 모든 대응
문항은 정답을 포함하지 않는 3행 표를 사용하며 1280·768·390·360px의
밝은/어두운 화면에서 행 우선 읽기 순서, 접근성 설명, 셀 넘침을 검사한다.
비율·백분율·함수·변수·정비례·그래프·좌표·두 연산 관계는 제외하고
`review` 상태와 DB 비발행 경계를 유지한다.

최종 콘텐츠 체크섬은
`b106efcdf8275b412b6a917fd657d812581ed99e983ead090c030a624d891f6e`다.
최종 게이트는 Vitest 60파일 484테스트, DB 26파일 430테스트,
전체 타입 검사·빌드·교차표 재현성·79파일 콘텐츠 감사, 5학년 표적
Playwright 2시나리오를 통과했다. Kiro Opus 5 재검증은 첫 검증의
medium 3건과 테스트 누락 3건이 닫혔음을 확인하고 `VERDICT: APPROVE`,
blocker·high·medium 0건, `NEXT_UNIT_READINESS: READY`를 반환했다.

## A4-4 — 약분과 통분

상태: **7단계·14문항 구현·자동 회귀·Kiro Opus 5 보완 재검증 통과**

- `frac-equiv.multiply-both`: 분자와 분모에 같은 수를 곱해 크기가 같은
  분수를 만든다.
- `frac-equiv.divide-both`: 분자와 분모를 같은 수로 나누어 약분한다.
- `frac-equiv.simplest-form`: 공약수가 1만 남는 기약분수까지 약분한다.
- `frac-equiv.common-denominator`: 공통분모가 되는 배수를 찾아 통분한다.
- `frac-compare.different-denominator`: 분모가 다른 분수를 같은 기준에서
  비교한다.
- `frac-decimal.convert`: 분수와 소수를 서로 바꾸어 나타낸다.
- `frac-decimal.compare`: 분수와 소수를 같은 형태로 바꾸어 비교한다.

각 단계는 direct·transfer 두 문항과 반복되는 두 오개념을 가진다.
기약분수 단계의 `한 번 약분하고 멈춤`만 정답과 같은 유리수인 오답을
허용하며 정답은 gcd 1, 해당 오답은 gcd 1 초과여야 한다. 비교 네 문항만
질문의 후보를 선택지에 그대로 옮기는 것을 허용한다. 14문항은 답을
노출하거나 장식이 되는 그림을 쓰지 않고 `visual:none`으로 제공한다.

첫 Kiro 독립 검증은 비교 문항 한 개의 오답 산출 근거 불일치와 목표
분모만 보고 오답을 제거할 수 있는 세 문항을 찾아냈다. 비교 후보와
오개념 제목을 다시 맞추고, 목표 분모 문항의 모든 선택지 분모를 통일했다.
오라클도 42개 하드코딩 문자열 대조에서 28개 오답을 순수 산출 함수로
재생성하는 방식으로 강화했다.

보완 후 콘텐츠는 네 단원·22단계·44문항이며 4단원 카드는 14문제·약
7분이다. canonical checksum은
`b27fb6571b22adc15cc7733b7fdc9fc0a808fd1fb094420311303017d392a1c8`이다.
최종 Kiro 재검증은 첫 검증의 high 1건, medium 3건, low 4건이 모두
닫혔음을 확인하고 `VERDICT: APPROVE`, blocker·high·medium 0건,
`NEXT_UNIT_READINESS: READY`를 반환했다. 변경 범위 검증은 Vitest 61파일
499테스트, DB 27파일 440테스트, 타입 검사·빌드·교차표 재현성·80파일
콘텐츠 감사와 5학년 학생·교사 Playwright 2시나리오를 통과했다.

## A4-6 — 다각형의 둘레와 넓이

상태: **7단계·14문항 구현·자동 회귀·실브라우저·독립 재검증 완료**

- `pa.perimeter`: 직사각형과 정사각형의 둘레를 한 바퀴의 길이로 구한다.
- `pa.area-unit`: 교실 바닥과 공책 표지에 알맞은 넓이 단위를 구별한다.
- `pa.rectangle-square-area`: 직사각형과 정사각형의 넓이를 구한다.
- `pa.parallelogram-area`: 밑변과 수직 높이를 사용해 평행사변형의 넓이를 구한다.
- `pa.triangle-area`: 밑변×높이를 한 번 더 2로 나눈다.
- `pa.trapezoid-area`: 평행한 두 변을 더한 뒤 높이를 곱하고 2로 나눈다.
- `pa.rhombus-area`: 두 대각선의 곱을 2로 나눈다.

각 단계는 direct·transfer 두 문항과 반복되는 두 오개념을 가지며 총
14문항·28오답 근거다. `[6수03-11]`~`[6수03-14]` 네 성취기준을 단원 하나에
배치하고, 다각형의 구성 원리 일반화나 원주·원 넓이는 이후 단원으로 남긴다.

도형은 정답을 암시하는 칸 수나 분할 조각을 사용하지 않고, 문제에서 준
길이만 표시한다. 직사각형의 가로·세로, 평행사변형·삼각형의 밑변·높이,
사다리꼴의 윗변·아랫변·높이, 마름모의 두 대각선은 같은 축척으로 그려
수치와 모양이 충돌하지 않게 한다. 높이는 점선과 직각 표식, 마름모의 두
대각선은 교점의 직각 표식으로 구별한다. 1280×720, 768×1024, 390×844
실화면에서 가로 넘침, 수치 라벨 겹침, 도형 선 가시성을 검사했다.
첫 독립 검증은 오답 산출 오라클, 평행사변형·사다리꼴을 포함한 전체 도형
좌표 회귀, SQL 내부 함수 권한 검사의 부족을 지적했다. 28개 오답을 의미
ID별 계산 함수로 다시 산출하고 활성 도형 12개의 축척·높이·직각·대각선을
좌표로 고정했으며 내부 함수 5개의 `anon`·`authenticated` 실행 차단을
19개 pgTAP으로 검사했다. 같은 Codex 검증 서브에이전트의 보완 재검증은
blocker·high·medium·low 0건으로 `APPROVE`했다.
