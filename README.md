# Middle of Math

초등학생의 수학 풀이를 최종 정답만으로 판단하지 않고, 풀이 과정의 작은 판단 단위로 나누어 어디에서 이해가 흔들리는지 교사가 볼 수 있게 하는 진단 서비스입니다.

현재 1–3명의 초대 교사가 사용할 3학년 2학기 실교실 파일럿 경로를 구현하고 있습니다. 클래스 코드 입장, 오프라인 큐, Supabase 영구 저장, 최신 완료 세션 기반 반 요약, 분리된 교사·학부모 리포트와 내부 콘텐츠 스튜디오를 포함합니다. 기존 `수 세기·5학년 분수` 정적 프로토타입은 회귀 fixture로 루트에 보존합니다.

## 왜 만들게 되었나

기존 수학 학습 서비스는 학생이 마지막에 낸 답이 맞았는지 틀렸는지를 중심으로 보여주는 경우가 많습니다. 하지만 교사가 실제로 알고 싶은 것은 단순히 "틀렸다"가 아니라, 학생이 어느 단계에서 막혔는지입니다.

예를 들어 `1/2 + 1/3`을 틀린 학생도 이유는 서로 다를 수 있습니다.

- 분모가 다른 분수를 더하기 전에 같은 기준으로 맞춰야 한다는 생각을 못 했을 수 있습니다.
- `1/2`을 `3/6`으로 바꾸는 동치분수 변환이 흔들렸을 수 있습니다.
- 통분은 했지만 마지막에 분모까지 더했을 수 있습니다.
- 문장제에서는 계산보다 먼저 어떤 연산을 해야 하는지 못 잡았을 수 있습니다.

이 프로젝트의 출발점은 이런 차이를 교사가 바로 볼 수 있게 만드는 것입니다.

## 핵심 아이디어

문제를 한 번에 풀게 하지 않고, 수학적 판단을 최대한 작게 분절합니다.

학생은 매 단계에서 하나의 선택을 합니다. 시스템은 그 선택, 선택까지 걸린 시간, 선택 변경 여부, `잘 모르겠어요` 사용 여부를 기록합니다. 수 세기에서는 사물을 누른 순서와 중복·누락도 함께 기록합니다. 교사 화면은 이 원자료를 "어느 개념을 먼저 확인해야 하는지"에 가까운 근거로 정리합니다.

## Phase 1 알파 범위

- 기준 학기: 초등 3학년 2학기
- 단원: 곱셈, 나눗셈, 원, 분수, 들이와 무게, 그림그래프
- 콘텐츠: 6개 단원·12개 판단, Zod 검증, 버전 `1.0.0`
- 학생: 클래스 코드 + 번호 + 학생별 6자리 개인 코드 입장, 앞으로만 진행, IndexedDB 오프라인 큐
- 교사: 반 요약 첫 화면, 학생 근거 드릴다운, 진단 배정, 번호·선택 별칭·일회 노출 개인 코드 관리
- 리포트: 교사용 근거와 학부모 공유용 인쇄/PDF 화면 분리
- 백엔드: Supabase Auth·Postgres·RLS, append-only 관찰 이벤트

## Phase 2 콘텐츠 스튜디오

- 내부 제작자·검수자·관리자 전용 `apps/studio`
- 초등 1–6학년 콘텐츠 모델, 첫 파일럿은 3학년 2학기
- 자동 저장과 리비전 충돌 방지
- 단원 → 학습 단계 → 판단 단위 구조 편집과 실제 학생 화면 미리보기
- 제작자와 다른 검수자의 승인 뒤 semantic version 발행
- 교사용 해석과 학부모용 설명 문구 분리
- Supabase 발행본 전체 JSON을 운영 원장으로 사용
- DB가 발행 직전 전체 무결성을 다시 검사하고 canonical JSON SHA-256을 직접 계산
- 교사는 발행본을 실제 클래스에 고정 버전으로 배정하고, 학생은 자기 과제 버전만 조회

## 중요한 설계 결정

### 한국 교육과정 지도는 뼈대로만 사용한다

수 세기 MVP는 [DECK6/korean-elementary-learning-map](https://github.com/DECK6/korean-elementary-learning-map)의 안정적인 성취기준·주제 ID를 교육과정 앵커로 참고합니다. 학생용 문항이나 개별 학습자 진단 문구를 가져오지는 않습니다.

현재 연결은 데이터 `kr-full-depth-v0.4`, 온톨로지 `0.3.0-p3`, 커밋 [`3ef0563`](https://github.com/DECK6/korean-elementary-learning-map/tree/3ef0563084aa2a9baaa47da2c1ec0ebf5d7edc5c)을 기준으로 확인했습니다. 외부 지도가 갱신되더라도 검토 없이 ID 의미가 바뀌지 않도록 이 참조점을 기록합니다.

- `kr-2022-elem-math:[2수01-01]`: 1~2학년군 수와 연산, `네 자리 이하의 수` 모듈에서 수 세기·읽기·쓰기와 수-양 연결 범위를 참고
- `kr-2022-elem-math:[2수01-03]`: 같은 학년군·영역·모듈에서 수의 차례와 크기 비교 범위를 참고
- `kr.mt.math.number-operations.g1-2.s2-01-01.*`, `...s2-01-03.*`: 개념·표현·적용 주제 ID 연결

성취기준 원문은 화면이나 데이터에 옮기지 않습니다. 화면의 짧은 설명과 아래 7개 학습 단계는 Middle of Math가 진단 관찰을 위해 작성한 것이며, 교육부·NCIC 또는 원 저장소의 공식 승인이나 개별 학생에 대한 확정 진단을 뜻하지 않습니다.

### 교육과정과 관찰 사이에 작은 학습 단계를 둔다

기존 다섯 진단 축은 관찰 결과를 묶는 내부 하위 능력으로 유지합니다. 별도로 다음 7개 단계를 앞에서부터 살펴보는 MVP용 선수 구조를 둡니다.

1. 수 이름을 붙여 하나씩 세기
2. 센 수를 전체 개수로 알기
3. 순서와 놓인 모양이 달라도 개수 알기
4. 개수와 숫자 연결하기
5. 두 수의 많고 적음 비교하기
6. 앞뒤 수를 이어 세기
7. 같은 수만큼 뛰어 세기

교사 화면은 `교육과정 앵커 → 작은 학습 단계 → 선택·조작 근거`를 이어 보여주고, 현재 세션에서 가장 먼저 다시 살펴볼 단계를 표시합니다. 한 번의 정답이나 오답만으로 숙달 또는 부족을 확정하지 않습니다.

### 학생에게 진단 문구를 보여주지 않는다

학생 화면에는 정답 여부, 오답의 특징, 오개념 이름, 교사용 해석 문장을 보여주지 않습니다. 그런 문구가 학생 선택지 아래에 보이면 학생이 수학적으로 판단하는 것이 아니라 문구 힌트를 보고 맞출 수 있기 때문입니다.

학생 화면의 선택지는 짧은 답 후보만 보여줍니다. `좋은 방법`, `전략`, `빠뜨리지 않기`처럼 어휘 이해를 따로 요구하는 질문은 쓰지 않고, 그림을 누른 실제 행동에서 중복·누락 근거를 얻습니다.

### 정답 막대를 먼저 보여주지 않는다

분수막대는 학생이 생각할 수 있도록 돕는 도구지만, 정답 자체를 먼저 보여주면 문제가 성립하지 않습니다. 그래서 `1/2`와 같은 크기를 찾는 단계에서는 기준 막대만 보여주고, `2/4` 같은 정답 막대는 선택지로만 남깁니다.

`2/3 = ?/9` 같은 변환 단계도 `6/9` 막대를 보여주지 않고 `?/9`처럼 빈 기준 막대로 표시합니다.

### 학생 흐름은 앞으로만 진행한다

초기에는 이전 단계로 돌아가는 기능도 고려했습니다. 하지만 뒤 단계에서 본 정보가 앞 단계 판단을 오염시킬 수 있다는 문제가 있었습니다. 예를 들어 뒤에서 정답 단서를 본 뒤 앞 단계로 돌아가면, 처음부터 이해한 것인지 나중에 본 단서를 이용한 것인지 구분하기 어렵습니다.

현재 학생 화면은 앞으로만 진행합니다.

### 완료된 실제 세션만 반 요약에 집계한다

처음에는 샘플 학생 데이터를 섞어 반 전체 요약처럼 보이게 했지만, 그러면 사용자가 방금 푼 결과와 교사 진단이 연결되지 않는 문제가 생겼습니다.

Phase 1에서는 완료된 실제 학생 세션을 반 전체 요약에 집계합니다. 진행 중 기록은 오개념 집계에서 빼고 학생 수만 따로 표시하며, 샘플 데이터와 실제 기록을 섞지 않습니다. 교사는 반 신호에서 학생별 교사용 리포트와 판단 근거로 내려갈 수 있습니다.

## 학생 화면에서 수집하는 데이터

- 문제 ID
- 단계 ID
- 학생이 선택한 보기
- 선택이 가진 개념 신호
- 단계에 머문 시간
- 첫 선택까지 걸린 시간
- 선택 변경 횟수
- 선택 후 `다음`을 누르기까지의 확인 시간
- `잘 모르겠어요` 사용 여부
- 진단 세트 ID
- 3학년 2학기 교육과정 앵커 ID와 작은 학습 단계 ID
- 상호작용 유형과 버전
- legacy 수 세기 fixture에서는 사물을 누른 순서, 중복·누락 수

수집한 데이터는 학생에게 직접 진단처럼 보여주지 않고 교사 화면에서 해석합니다.

## 교사 화면에서 보는 것

교사 첫 화면은 선택한 클래스의 완료 세션을 같은 신호로 묶은 반 요약입니다. 각 신호에서 학생별 교사용 근거 리포트로 내려가며, 같은 해석 결과로 학부모 공유용 문장을 별도로 만듭니다.

- 완료 학생 수와 진행 중 학생 수
- 관찰한 판단 수
- 주의 신호 수
- 오개념 우선순위
- 학생별 풀이 흔적
- 선택, 시간 해석, 행동 신호

교사용 문장은 미사여구보다 짧고 직접적인 설명을 우선합니다.

## DeepSeek API 계획

현재 Phase 1 알파는 DeepSeek API를 호출하지 않습니다. 지금은 버전이 있는 규칙 기반 엔진으로 오개념 신호를 해석합니다.

향후 DeepSeek을 연결할 때도 개인정보를 보내지 않는 것이 원칙입니다. 전송 후보는 익명 요약 로그에 한정합니다.

보낼 수 있는 정보:

- 문제 ID
- 단계 ID
- 선택 신호
- 시간대 해석
- 선택 변경 수
- `잘 모르겠어요` 사용 여부
- 선택 후 확인 시간

보내지 않을 정보:

- 학생 이름
- 학교 식별 정보
- 개인을 식별할 수 있는 원문
- 불필요한 자유 서술 원문

## 하네스가 막는 회귀

기존 프로토타입의 콘텐츠·런타임 하네스와 새 패키지 테스트를 함께 유지합니다. 다음 문제가 다시 들어오면 실패합니다.

- 학생 선택지에 진단 하단 문구를 렌더링하는 경우
- 학생 선택지에 `오개념`, `피드백`, `진단`, `고른 선택` 같은 진단성 문구가 들어가는 경우
- 분수막대가 정답 선택지를 직접 보여주는 경우
- 이전 단계 버튼이나 뒤로가기 로직이 다시 들어오는 경우
- 교사 진단이 샘플 학생 데이터를 현재 세션과 섞는 경우
- 수 세기 14개 개념 ID나 5개 진단 축 연결이 누락된 경우
- 한국 교육과정 앵커·주제 ID 또는 7개 순서형 학습 단계 연결이 누락된 경우
- 언어 중심의 `c2-strategy` 문항이나 저학년에게 불필요하게 어려운 전략 표현이 다시 들어오는 경우
- 사물 누르기, 수 배열, 수직선 상호작용이 빠진 경우
- 사물 누른 순서와 중복·누락 근거가 교사 화면까지 전달되지 않는 경우
- 진단 선택 화면에서 수 세기 또는 기존 분수 세트가 빠진 경우

## 실행 방법

의존성을 설치하고 로컬 Supabase를 시작합니다.

```bash
npm install
colima start
npx supabase start --exclude vector
```

학생 앱, 교사 앱, 내부 콘텐츠 스튜디오를 각각 실행합니다.

```bash
npm run dev:student  # http://127.0.0.1:4173
npm run dev:teacher  # http://127.0.0.1:4174
npm run dev:studio   # http://127.0.0.1:4175
```

세 앱은 운영 설정 누락 시 자동으로 샘플 데이터에 내려가지 않습니다. 로컬 데모가 필요할 때만 각 앱에 `VITE_DEMO_MODE=true`를 명시합니다. staging과 production은 `VITE_DEMO_MODE=false`, `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`를 각각 분리해 설정합니다.

## 파일럿 개방 전 남은 운영 작업

- GitHub `staging` environment에 Supabase access token·DB password·project ref와 Vercel token, smoke 교사 계정을 등록
- 별도 production Supabase 프로젝트 생성 후 production environment 비밀값과 Auth redirect URL 등록
- staging 자동 migration·배포에서 초대 교사 → 학생 완료 → 반 요약 → 학부모 출력 smoke 통과
- staging에서 검증한 정확한 커밋 SHA를 production 수동 승인으로 승격

세부 체크리스트와 보존 작업은 [`docs/pilot-operations.md`](docs/pilot-operations.md)를 따른다. Phase 2 구조 편집 확장과 Phase 3 DeepSeek 익명 요약은 파일럿 이후 범위다.
